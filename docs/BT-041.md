# BT-041 / Issue #41 — Gemini 채팅 답장 3개 추천·선택 입력

담당 E / P1. 선행 BT-010(UI 목업)·BT-024(게이트웨이)·BT-034(방 연결). 공통 계약은 [BT-024](./BT-024.md), 방과 약속 구분은 [BT-034](./BT-034.md).

## 1. 동작 요약

1. 사용자가 채팅 입력창 옆 **반짝이 버튼을 눌렀을 때만** 앱이 `suggestChatReplies({matchId})` 를 부른다. 메시지마다 자동으로 부르지 않는다.
2. 서버가 `matches/{matchId}.chatRoomId` 의 RTDB 최근 메시지를 직접 읽어 Gemini 에 보낸다. 앱은 메시지 본문·UID 를 보내지 않는다.
3. 서로 다른 답장 3개를 칩으로 보여 준다. 칩을 누르면 **입력창에만 들어가고**, 사용자가 고친 뒤 직접 전송한다. **자동 전송하지 않는다.**
4. 실패하면 칩을 숨기고 안내만 한다. 채팅·직접 입력은 그대로 쓸 수 있다.

## 2. 서버 (`functions/src/ai`)

### 권한·상태 (차감 전에 검사)

| 상황 | 응답 |
|---|---|
| 매칭 없음·비참여자 | `PERMISSION_DENIED` (존재 여부를 알리지 않음) |
| 방에서 나감(`chatRooms/{chatRoomId}/members/{uid}` 없음) | `PERMISSION_DENIED` |
| 보관된 방(`control.archived=true`)·전송 불가(`control.writable=false`) | `PERMISSION_DENIED` |
| 방 준비 전(`chatRoomId` 없음·`control.chatReady=false`) | `AI_UNAVAILABLE` (retryable) |
| ENDED 매칭 | 허용 (종료 후에도 채팅 유지) |

- 재사용된 방은 약속 ID 와 방 키가 다르다. 서버는 항상 `chatRoomId` 경로를 읽고 `chatRooms/{matchId}` 를 직접 읽지 않는다.
- Mock 모드는 BT-024 문서대로 `matches` 참여자만 확인한다(RTDB 에뮬레이터 없이 개발 가능).

### Gemini 에 보내는 내용 (입력 최소화)

```json
{ "purpose": "스터디", "messages": [ { "from": "상대", "text": "안녕하세요! 같이 공부하실래요?" }, { "from": "나", "text": "좋아요" } ] }
```

- 최근 **20개**, 메시지당 **200자**. 호출자 기준 `나/상대` 로만 표시한다. 닉네임·UID·시각·방 키는 보내지 않는다.
- 메시지의 연락처(이메일·전화번호·링크·오픈채팅/SNS 링크)는 지우고 보낸다. 연락처만 있던 메시지와 참여자가 아닌 발신자의 메시지는 뺀다.
- 목적은 매칭 스냅샷의 `purpose`. `전체`·빈 값이면 `null`.
- 대화가 비어 있으면 목적을 바탕으로 첫인사 답장을 만든다.
- 프롬프트는 대화 안의 지시문을 따르지 않고, 대화에 없는 시각·장소·이름을 지어내지 않으며(필요하면 묻는 문장), 연락처를 넣거나 요구하지 않고, 데이팅 톤을 쓰지 않도록 한다.

### 응답 검사

- 스키마: 정확히 3개, 각 1~50자(앞뒤 공백 제거).
- `verify`: 공백을 정리한 뒤 연락처가 있으면 `AI_INVALID_OUTPUT`(게이트웨이가 1회 재시도), 대소문자·공백만 다른 중복도 `AI_INVALID_OUTPUT`.
- 하루 한도 50회, 제한 시간 10초(BT-024 표).

### 연락처 패턴

`generateProfile`(B, BT-029)과 같은 기본 패턴에 점으로 구분한 전화번호(`010.1234.5678`)와 `http`·`www` 없는 `open.kakao.com`·`instagram.com`·`t.me`·`discord.gg` 링크를 더 막는다. 시각(`14:00`)·학번 8자리는 걸리지 않는다. 자기소개 초안(`generateProfile`, B)과 매칭 평가 입력(`matching/score.ts`, A)도 이 공통 파일을 쓴다(2026-11-28).

한계: 연락처를 여러 메시지로 나눠 보내면(예: `010-1234` / `5678`) 각 메시지는 패턴에 걸리지 않는다. SNS 아이디(`@abc`)만 쓴 경우도 지우지 않는다. 출력 검사는 같은 패턴으로 답장에 연락처가 다시 나오는 것을 막는다.

## 3. 앱 (`chat/`)

| 파일 | 내용 |
|---|---|
| `ReplySuggestionRepositories` | Firebase 가 설정되면 `FunctionsReplySuggestionRepository`, 아니면 BT-010 `MockReplySuggestionRepository`. `targetMatchId`: 상단 대표 약속 → 모두 종료면 가장 늦게 끝난 약속 → 약속 목록이 없으면 방 키 |
| `FunctionsReplySuggestionRepository` | `asia-northeast3` Callable. 취소·호출 중 계정 변경 시 결과를 쓰지 않음. 응답이 서로 다른 3개가 아니면 칩을 만들지 않음 |
| `ReplySuggestionFailure` | BT-024 오류 표 → 화면 처리 분류 |
| `ChatRoomActivity` | 기존 반짝이 버튼·칩(`item_chat_reply_chip`)·`fillInput` 재사용. 요청 중 버튼 잠금 |

| 분류 | 서버 사유 | 화면 |
|---|---|---|
| `RETRY` | `AI_TIMEOUT`, `AI_INVALID_OUTPUT`, `AI_RATE_LIMITED`, retryable `AI_UNAVAILABLE`, 네트워크 | 칩 숨김 + "다시 눌러주세요" |
| `QUOTA` | `QUOTA_EXCEEDED` | 칩 숨김 + "오늘 횟수를 모두 썼어요. 직접 입력" |
| `PERMISSION` | `PERMISSION_DENIED` | 칩 숨김 + 권한 안내 |
| `BLOCKED` | `AI_BLOCKED` | 칩 숨김 + 응답 불가 안내 |
| `UNAVAILABLE` | `AI_NOT_IMPLEMENTED`, retryable 아닌 `AI_UNAVAILABLE` | 칩 숨김 + 안내, **이 화면에서 반짝이 버튼 숨김** |
| `SIGNED_OUT` | `UNAUTHENTICATED`, 호출 중 계정 변경 | 로그아웃 상태면 온보딩으로 |
| `GENERIC` | `INVALID_INPUT`, `INTERNAL`, 모르는 사유 | 칩 숨김 + 일반 안내 |

재시도는 자동으로 하지 않고 사용자가 반짝이 버튼을 다시 누른다.
