# BT-030 프로필·인증 예외 처리 및 계정 재접속 복원 (Issue #30)

담당: B (인증/프로필) · 선행: BT-013(#13), BT-014(#14)

## 첫 화면 결정 (앱 재실행)

```
온보딩 시작
 ├─ 로그인 안 됨 → 온보딩 그대로(시작하기)
 └─ 로그인 됨 → 세션 확인(checkSession: Firebase user.reload)
      ├─ EXPIRED(계정 삭제·토큰 무효) → 로그아웃 후 온보딩 + "로그인이 만료됐어요. 다시 로그인해 주세요"
      ├─ DISABLED(관리자가 사용 중지) → 로그아웃 후 온보딩 + "사용이 중지된 계정이에요. 관리자에게 문의해 주세요"
      └─ VALID / UNKNOWN(네트워크 등) → 프로필 완료 확인
           ├─ 완료 → 메인
           ├─ 미완료 → 가입 단계(시간표 → 프로필)
           └─ 조회 실패 → 온보딩에 머물고 "다시 시도"(메인으로 보내지 않음, #79)
```

- 네트워크가 없으면 세션을 확인하지 못해도 로그아웃시키지 않는다(UNKNOWN → 기기의 로그인으로 진행, 프로필은 Firestore 캐시로 확인).
- 메인과 온보딩은 같은 기준(로그인 여부)으로만 서로를 보내므로 둘 사이를 오가는 무한 루프가 없다. 만료면 이미 로그아웃된 상태라 다음 실행도 온보딩에 머문다.
- 확인 중에는 온보딩 문구·버튼을 숨겨 가입한 사용자에게 가입 화면이 잠깐 보이지 않게 한다(#79).

사용 중지된 계정은 다시 로그인해도 막히므로 "만료"로 안내하지 않는다. 메일 링크로 로그인을 시도할 때도(`ERROR_USER_DISABLED`) 같은 안내를 띄우고 이메일 입력 화면으로 돌린다(#101 작성자 실기기 확인에서 발견).

## 사용 중 세션 끊김

`SessionGuard`(auth/)를 메인 화면이 쓴다.

| 시점 | 동작 |
|---|---|
| 메인이 다시 보일 때(onStart) | Firebase 모드에서 로그아웃 상태면 온보딩으로(만료 안내) |
| 메인이 보이는 동안 | Firebase 가 로그아웃시키면(AuthStateListener) 바로 온보딩으로(만료 안내) |
| 마이페이지에서 직접 로그아웃 | `SessionGuard.signOutByUser`: 캐시 정리 → 로그아웃 → 온보딩. 감시가 이를 만료로 보지 않아 이동이 겹치거나 "만료" 안내가 잘못 뜨지 않는다 |

Mock 모드는 로그인을 메모리에만 두므로 감시하지 않는다.

## 인증 미완료 복원

링크를 보낸 뒤 앱을 껐다 켜서 인증 화면에 다시 오면(링크로 연 게 아님) 이메일 입력부터 다시 시키지 않고 **"이메일을 확인해 주세요"(Figma 235:1961)** 상태로 돌려놓는다. 보낸 이메일은 이 기기 SharedPreferences 에만 있다(BT-013). 재발송·이메일 다시 입력은 그 화면 버튼 그대로다. 로그아웃하면 보낸 이메일을 지운다.

## 계정 변경 시 정보 잔존 방지

- 로그아웃 시: 보낸 이메일 삭제(BT-013), 프로필 사진 캐시 비움(`ProfileRepository.clearSessionCaches` → `PhotoLoader.invalidateAll`, 진행 중 다운로드 결과도 캐시에 넣지 않음), 모든 화면을 닫고 온보딩으로.
- 계정별 데이터는 UID 로 나뉜다: 프로필 `users/{uid}`·`publicProfiles/{uid}`, 요청·채팅 저장소는 UID 가 바뀌면 새로 만들고(`RequestRepositories`, `ChatRepositories`), 시간표 공강 저장 큐는 소유 UID 를 확인한다(BT-015/016).

## 오프라인 저장

- Firestore 는 오프라인 쓰기를 기기에 보관하고 서버가 받을 때까지 끝내지 않는다(오류 없음). 그래서 비행기 모드에서 저장을 누르면 버튼이 눌린 채 연결될 때까지 기다리고, 저장 중에는 뒤로가기도 막혀(#79) 화면에 묶였다.
- 저장 시작 전에 인터넷 연결을 확인해(`common/NetworkStatus.isOnline`, 시간표 저장 BT-026도 함께 씀) 없으면 "네트워크 연결을 확인해 주세요. 연결된 뒤 다시 저장할 수 있어요"만 띄우고 시작하지 않는다.
- 저장 도중 끊기면 사진 업로드가 기본 10분 재시도하던 것을 20초로 줄여(`FirebaseStorage.setMaxUploadRetryTimeMillis`) "네트워크 연결을 확인해 주세요"로 끝낸다. 이 설정은 앱의 `FirebaseStorage` 기본 인스턴스 전체에 적용된다(시간표 이미지 업로드 BT-025 포함, C 와 공유).
- 남은 경우: 사진 없이 저장하는 도중(Firestore 쓰기 단계)에 끊기면 연결될 때까지 기다린다. 쓰기는 기기에 보관돼 연결되면 반영된다.

## 이미지 미등록·학과 검색

- 사진이 없거나 불러오지 못하면 기본 이미지를 유지한다(마이페이지·수정 화면·매칭 카드). 사진은 선택 사항이며 저장을 막지 않는다.
- 학과 검색: 결과가 없으면 "검색 결과가 없어요 / 다른 검색어로 다시 찾아보세요". 검색 화면에서 뒤로 나오면 기존 학과를 그대로 둔다(BT-014).

## 검증 범위

실제 Firebase 에서 계정을 삭제·비활성화해 만료를 만드는 시험은 운영 계정을 바꾸는 일이라 하지 않았다. 만료 판정은 오류 코드 단위 테스트로 확인했다. 실제 Firebase 계정 로그아웃 → 다른 계정 로그인 전환은 학교 이메일 링크가 필요해 팀 2계정 검증(BT-023)에서 함께 본다.
