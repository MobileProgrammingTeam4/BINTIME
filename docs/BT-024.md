# BT-024 / Issue #24 — Gemini Cloud Functions 공통 게이트웨이·응답 스키마

앱은 Gemini 를 직접 호출하지 않는다. 모든 AI 기능은 Cloud Functions Callable 을 거치고, Gemini API 키는 서버 비밀값(Secret Manager `GEMINI_API_KEY`)에만 있다. 이 문서는 게이트웨이를 쓰는 팀원(A·B·C·E)을 위한 계약과 사용법이다.

- 서버 코드: `functions/` (TypeScript, Node.js 24, firebase-functions v2)
- 리전: **`asia-northeast3`(서울)**. 앱은 반드시 `FirebaseFunctions.getInstance("asia-northeast3")` 로 호출한다.
- 모델: `gemini-3.5-flash-lite` (`functions/.env.bintime-mobile` 의 `GEMINI_MODEL`)
- 학교 이메일 허용 접미사: `ALLOWED_EMAIL_SUFFIXES` (1장 「Functions 환경 설정」)
- 배포: `bintime-mobile` 프로젝트에 5개 Callable 배포·운영 확인 완료(aiPing 실제 호출 200, 미로그인 401)

> **Gemini 키는 2026-11-21 에 같은 키 그대로 유료(Tier 1) 등급으로 전환했다.** 그 전(무료 등급)에는 입력이 Google 서비스 개선에 쓰일 수 있어 테스트 데이터만 보냈다. 비용은 기능별 하루 한도로 계속 제한한다.

### 공통 처리 순서 (`functions/src/ai/gateway.ts`)

1. 로그인 확인 — UID 는 Auth 토큰에서만 읽는다(요청 본문 UID 사용 안 함). 이어서 **학교 이메일 확인**(Callable 만, `functions/src/ai/emailPolicy.ts`): 토큰의 `email_verified === true` 이고 이메일 도메인이 `ALLOWED_EMAIL_SUFFIXES` 중 하나로 끝나야 한다. 실패하면 `PERMISSION_DENIED` 이고 사용량은 차감하지 않는다. 서버 내부 함수 `evaluateMatch` 는 호출한 함수가 인증한 uid 를 넘기므로 이 검사를 하지 않는다
2. 입력 검증 — 기능별 zod 스키마. 실패 시 필드 경로만 알려 주고 값은 돌려주지 않는다
3. 권한 검사 — 채팅 참여자(`matches/{matchId}.participantUids`), 본인 Storage 경로 등
4. 하루 호출량·최소 호출 간격 — `aiUsage/{uid}_{YYYY-MM-DD}`(Asia/Seoul) 트랜잭션. 하루 한도 초과는 `QUOTA_EXCEEDED`, 작업에 최소 간격(`minIntervalMs`)이 있고 같은 사용자의 직전 호출이 그 안이면 `AI_RATE_LIMITED`(retryable). 입력 오류·권한 거절·간격 위반은 차감하지 않음
5. Mock 응답 또는 Gemini 호출 — JSON 응답 스키마 지정, 기능별 제한 시간, 429·5xx·형식 오류만 1회 재시도
   - **제한 시간(`timeoutMs`)은 재시도까지 포함한 전체 시간이다(#48).** 두 번째 시도는 남은 시간만 쓰고, 0.5초 대기 뒤 남은 시간이 제한 시간의 절반(`MIN_RETRY_BUDGET_RATIO`)보다 적으면 재시도하지 않고 첫 오류를 돌려준다(`ai_call` 로그 `retrySkipped: "budget"`).
   - SDK 는 이 시간을 Google 쪽 마감으로도 보낸다. 마감이 지나 돌아온 `504 DEADLINE_EXCEEDED`는 우리 시간 초과와 같게 `AI_TIMEOUT`으로 보고 재시도하지 않는다. 마감 표시가 없는 504 와 다른 5xx·429 는 그대로 1회 재시도한다.
   - 응답 스키마는 `toGeminiSchema(task.output, task.geminiSchema)` 로 만든다. 기본(`full`)은 output zod 스키마의 제약을 모두 보낸다. 작업이 `geminiSchema: "typesOnly"` 를 켜면 숫자 범위·문자열 길이·패턴·배열 개수 제약을 빼고 구조(타입·필수 필드·null 허용·추가 필드 금지)만 보낸다. 뺀 제약은 6단계가 그대로 검사한다.
   - 이유: 큰 스키마에 제약이 많으면 Gemini 가 400 `too many states for serving` 으로 거부한다. 다시 시도해도 같아서 `AI_UNAVAILABLE`(retryable false)이 된다. 현재 `typesOnly` 는 analyzeTimetable 만 켠다(2026-11-18 운영 실패, 로컬 재현으로 확인)
6. 응답 검증 — 스키마 + 규칙(답장 3개·중복 금지, 점수 0~100, 허용 목록 밖 장소 제거 등)
7. 기록 — Cloud Logging `ai_call`(기능, 결과, 시도 횟수, 지연, 토큰 수, 실패 시 Gemini HTTP 상태 코드). 프롬프트·응답 원문·키는 남기지 않는다

| 기능 | 제한 시간(재시도 포함 전체) | 하루 한도(사용자별) | 최소 호출 간격 |
|---|---|---|---|
| aiPing | 10초 | 50 | 없음 |
| analyzeTimetable | 55초(BT-048, 함수 120초, 512MiB, **동시 실행 4**) | 10 | 없음 |
| generateProfile | 10초 | 5 | 10초 |
| evaluateMatch | 10초 | 300 (검색한 사용자 기준) | 없음 |
| recommendPlace | 10초 | 30 | 없음 |
| suggestChatReplies | 10초 | 50 | 없음 |

배포 옵션은 `createAiCallable(task, { timeoutSeconds, memory, concurrency })`로 작업별로 바꾼다. 넘기지 않으면 제한 시간 30초·256MiB·최대 인스턴스 10, 동시 실행은 플랫폼 기본값(CPU 1 이상이면 80)이다. analyzeTimetable 은 요청 하나가 이미지 원본·base64·요청 본문으로 대략 50~70MB를 써서 동시 실행을 4로 제한했다(최대 동시 40건, #112 리뷰 C). 설정은 `test/callable-options.test.ts`가 확인한다.

**analyzeTimetable 메모리 기준 (#115 리뷰)**
- 여유: 요청 하나가 약 70MiB 라 4건이 동시에 돌면 약 380~430MiB, 최악이면 512MiB 에 거의 닿는다(추정, 측정값 아님).
- 확인: Cloud Monitoring 에서 Cloud Run 서비스 `analyzetimetable` 의 컨테이너 메모리 사용률(Memory utilization) 최댓값을 본다. 호출 한두 번은 기본 사용량만 보여 주므로, #113 병합 뒤 실제 호출이 쌓이면 다시 본다.
- 기준: 최댓값이 **70%(약 358MiB)를 넘으면** 아래 중 하나로 바꾼다. 바꿀 때는 `functions/src/index.ts` 를 PR 로 고치고 `--only functions:analyzeTimetable` 로 배포한 뒤 `functions:list` 로 확인한다.
  - 동시 실행 4 → 2 (메모리 단가는 같고, 몰릴 때 인스턴스가 더 뜬다. 최대 동시 20건)
  - 메모리 512MiB → 1GiB (동시 실행 4 유지, 실행 중 메모리 단가 두 배)
- 동시 실행을 1보다 크게 두려면 CPU 가 1 이상이어야 한다(1 미만이면 동시 실행이 1로 강제됨). 메모리를 바꿔도 `functions:list` 에서 CPU 를 확인한다.

### Functions 환경 설정

공개 설정(비밀값 아님)은 `functions/.env.<프로젝트>` 에 두고 커밋한다. 비밀값(`GEMINI_API_KEY`)은 Secret Manager 에만 둔다.

| 키 | 파일 | 값 | 설명 |
|---|---|---|---|
| `GEMINI_MODEL` | `.env.bintime-mobile` | `gemini-3.5-flash-lite` | live 호출 모델 ID |
| `AI_MODE` | (선택) `.env.local` | `mock` / `live` | 비우면 에뮬레이터 mock, 배포 live |
| `ALLOWED_EMAIL_SUFFIXES` | `.env.bintime-mobile`(배포), `.env.demo-bintime`(Mock 에뮬레이터), `.env.example` | `.ac.kr,.edu` | 학교 이메일 허용 접미사. 쉼표 구분 |

`ALLOWED_EMAIL_SUFFIXES` 규칙(PR #80 리뷰 1번. 허용 기준은 B 결정으로 앱과 같다):

- 앱 `auth/EmailVerificationState.java` 의 정규식 `^[a-zA-Z0-9._%+-]+@[a-zA-Z0-9.-]+\.(ac\.kr|edu)$`(대소문자 무시)과 같은 판단을 한다. 허용 목록만 코드 밖 설정으로 뺐다.
- 대소문자를 무시한다. 점으로 시작하지 않는 항목은 점을 붙인다(`ac.kr` → `.ac.kr`, `evilac.kr` 통과 방지). 형식이 잘못된 항목은 버린다.
- 도메인 **끝**이 접미사와 일치해야 하고 접미사 앞에 한 글자 이상 있어야 한다. `kookmin.ac.kr.evil.com`, `kookmin.ac.kr@evil.com`, `ac.kr` 은 거부한다.
- **값이 비어 있거나 유효한 항목이 없으면 모든 Callable 호출을 거부한다.** 허용 기준을 바꾸면 앱 정규식과 함께 바꾼다(B 와 합의).
- 거절하면 로그 `ai_callable_denied` 에 `task`, `requestId`, `uid`, `cause` 만 남긴다. **이메일 원문은 남기지 않는다.**

| `cause`(로그 전용) | 의미 |
|---|---|
| `NO_ALLOWED_SUFFIXES` | 서버 설정이 비어 있음(배포 설정 누락) |
| `EMAIL_MISSING` | 토큰에 이메일 없음(익명 로그인 등) |
| `EMAIL_NOT_VERIFIED` | `email_verified` 가 `true` 가 아님 |
| `EMAIL_DOMAIN_NOT_ALLOWED` | 허용 접미사로 끝나지 않음(형식 오류·접미사 속임수 포함) |

앱에는 네 경우 모두 `PERMISSION_DENIED` 하나로 보낸다(원인은 앱에 알려 주지 않는다).

## 2. 요청·응답 형식

시간 규칙은 BT-012·AGENTS.md 와 같다: 자정 기준 분, `[startMinute, endMinute)`, `dayOfWeek` 1(월)~7(일).

### 성공

```json
{
  "task": "suggestChatReplies",
  "data": { "replies": ["좋아요! 그때 봐요 :)", "혹시 시간 조금 늦춰도 될까요?", "어디서 만나면 좋을까요?"] },
  "meta": { "model": "gemini-3.5-flash-lite", "requestId": "…", "latencyMs": 1830, "mock": false }
}
```

`meta.mock == true` 이면 Mock 응답이다(에뮬레이터 기본값). 실제 성공으로 보고하지 않는다.

### 기능별 요청 → `data`

| 기능 | 요청(`data`) | 응답 `data` |
|---|---|---|
| aiPing | `{ message?: string(1~100) }` | `{ reply: string(1~200) }` |
| analyzeTimetable | `{ imagePaths: string[1~5] }` — 본인 Storage 경로 `timetableImages/{uid}/…` (**제안, BT-025 와 확정 필요**) | `{ courses: [{ name, dayOfWeek, startMinute, endMinute, building\|null, room\|null, confidence(0~1), sourceImageIndex }], warnings: string[] }` — 검수용 초안, 서버가 시간표에 바로 저장하지 않음 |
| generateProfile | `{ department, grade(1~6), preferredActivities?: string[≤10], courseNames?: string[≤20], draftBio?: string(≤150) }` — 이름·이메일·UID 보내지 않음 | `{ bio: string(1~150), suggestedTags: string[≤5] }` — 태그는 `#` 없이(BT-012 #3), 중복 없음. 소개에 연락처(이메일·전화·링크)가 있으면 `AI_INVALID_OUTPUT` |
| evaluateMatch (내부) | `{ overlapMinutes(≥60), purposes[], commonCourses[], searcher, candidate }` — side: `{ department, grade, tags[], bio?, nearbyBuildings[] }` | `{ score: 0~100 정수, reasons: string[1~3], suggestedActivity }` — 점수는 정렬용 내부 지표 |
| recommendPlace | `{ matchId }` — 목적·시간은 `matches` 스냅샷, 수업 건물은 두 사람 시간표에서 서버가 읽음 | `{ places: [{ placeId, name, reason }] 1~3 }` — 목적·운영 시간을 통과한 목록 장소 밖 id 는 버리고 이름은 서버 목록 값. 같은 약속은 저장된 추천을 횟수 차감 없이 돌려줌([BT-042](./BT-042.md)) |
| suggestChatReplies | `{ matchId }` — 메시지 본문은 앱이 보내지 않음(서버가 `matches/{matchId}.chatRoomId` 방의 RTDB 최근 메시지를 읽음, BT-041) | `{ replies: string(1~50)[3] }` — 서로 다름, 연락처가 있으면 `AI_INVALID_OUTPUT`. **앱은 입력창에만 넣고 자동 전송 금지** |

`matchId` 는 `[A-Za-z0-9_-]{1,128}`. 매칭 참여자가 아니거나 매칭이 없으면 둘 다 `PERMISSION_DENIED` 로 응답한다(존재 여부를 알려 주지 않음). ENDED 매칭도 참여자면 허용한다. `suggestChatReplies` 는 live 에서 현재 방 멤버인지(나가면 거부)·보관/전송 불가 방이 아닌지도 확인하고, 방이 아직 준비 전이면 `AI_UNAVAILABLE`(retryable) 로 응답한다(BT-041).

### 오류

모든 오류는 `HttpsError` 이고, 앱에서는 `FirebaseFunctionsException` 으로 받는다. `getDetails()` 는 `{ reason, retryable, requestId, fields? }` 이다. 메시지는 일반 문구이며 내부 원인·키는 담지 않는다. 문의 시 `requestId` 로 서버 로그를 찾는다.

| reason | 코드 | retryable | 앱 처리 |
|---|---|---|---|
| `UNAUTHENTICATED` | unauthenticated | false | 로그인 화면으로 |
| `PERMISSION_DENIED` | permission-denied | false | "권한이 없어요" 안내, 재시도 버튼 없음. 채팅 비참여자, 이메일 미인증·학교 이메일 아님(`ALLOWED_EMAIL_SUFFIXES`) 포함 |
| `INVALID_INPUT` | invalid-argument | false | 앱 버그. `fields` 로 원인 확인, 사용자에게는 일반 오류 |
| `QUOTA_EXCEEDED` | resource-exhausted | false | "오늘 AI 사용 횟수를 모두 썼어요", 수동 입력 유도 |
| `AI_RATE_LIMITED` | resource-exhausted | true | 잠시 후 다시 시도 버튼 |
| `AI_TIMEOUT` | deadline-exceeded | true | 다시 시도 버튼 |
| `AI_INVALID_OUTPUT` | internal | true | 다시 시도 버튼 |
| `AI_BLOCKED` | failed-precondition | false | "AI가 응답할 수 없는 내용이에요" |
| `AI_UNAVAILABLE` | unavailable | true(5xx·네트워크) / **false(키·결제·모델 설정 문제)** | `retryable` 대로. false 면 AI 기능 숨기고 수동 흐름 |
| `AI_NOT_IMPLEMENTED` | unimplemented | false | 아직 준비 안 된 기능. AI 버튼 숨김 |
| `INTERNAL` | internal | false | 일반 오류 |

**기능별 대체 흐름(핵심 기능은 AI 없이도 유지):** 시간표 인식 실패 → 수동 입력 / 자기소개 실패 → 직접 작성 / 매칭 점수 실패 → 점수 없이 겹침 시간순 / 장소 추천 실패 → 장소 줄 숨김 / 답장 추천 실패 → 칩 숨김 + 안내.

## 3. 서버 전용 데이터 `aiUsage`

`aiUsage/{uid}_{YYYY-MM-DD}` — `{ uid, date, counts: { <task>: n }, lastCalledAtMs: { <task>: epochMs }, total, updatedAt }`. `lastCalledAtMs` 는 허용된 호출마다 모든 작업에 대해 항상 기록하고(서버 시각), 최소 호출 간격이 있는 작업(현재 `generateProfile`)만 검사에 쓴다. 날짜 문서 단위라 자정을 넘는 간격은 보지 않는다. 서버(Admin SDK)만 쓴다. Firestore Rules 를 작성할 때 앱의 읽기·쓰기를 모두 거부해야 한다(현재 저장소에 `firestore.rules` 없음). README·AGENTS 5장에 반영했다.

## 5. (b) 앱(Java)에서 Callable 호출

앱에는 아직 Firebase 의존성이 없다. Firebase 연동 이슈에서 BoM 과 `firebase-functions`(및 `firebase-auth`)를 추가한 뒤 아래처럼 쓴다(참고용, 이 PR 은 앱 코드를 바꾸지 않았다).

```kotlin
// app/build.gradle.kts (참고) — 버전은 연동 시점의 최신 BoM 사용
dependencies {
    implementation(platform("com.google.firebase:firebase-bom:<version>"))
    implementation("com.google.firebase:firebase-functions")
    implementation("com.google.firebase:firebase-auth")
}
```

```java
import com.google.firebase.functions.FirebaseFunctions;
import com.google.firebase.functions.FirebaseFunctionsException;

import java.util.Collections;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/** 예: E · BT-041 답장 추천. Activity/Fragment 가 아니라 Repository 구현에서 호출한다. */
public final class FunctionsReplySuggestionSource {

    /** 모든 Callable 은 서울 리전이다. 기본 리전(us-central1)으로 부르면 NOT_FOUND 가 난다. */
    private final FirebaseFunctions functions = FirebaseFunctions.getInstance("asia-northeast3");

    public interface Callback {
        void onSuccess(List<String> replies);

        /** retryable 이면 "다시 시도" 버튼을, 아니면 칩 영역을 숨긴다. */
        void onError(String reason, boolean retryable);
    }

    public void suggest(String matchId, Callback callback) {
        Map<String, Object> data = new HashMap<>();
        data.put("matchId", matchId);   // 메시지 본문·UID 는 보내지 않는다

        functions.getHttpsCallable("suggestChatReplies")
                .call(data)
                .addOnSuccessListener(result -> {
                    @SuppressWarnings("unchecked")
                    Map<String, Object> body = (Map<String, Object>) result.getData();
                    @SuppressWarnings("unchecked")
                    Map<String, Object> payload = (Map<String, Object>) body.get("data");
                    @SuppressWarnings("unchecked")
                    List<String> replies = (List<String>) payload.get("replies");
                    callback.onSuccess(replies != null ? replies : Collections.emptyList());
                })
                .addOnFailureListener(e -> {
                    String reason = "INTERNAL";
                    boolean retryable = false;
                    if (e instanceof FirebaseFunctionsException) {
                        Object details = ((FirebaseFunctionsException) e).getDetails();
                        if (details instanceof Map) {
                            Map<?, ?> map = (Map<?, ?>) details;
                            if (map.get("reason") instanceof String) reason = (String) map.get("reason");
                            retryable = Boolean.TRUE.equals(map.get("retryable"));
                        }
                    }
                    callback.onError(reason, retryable);
                });
    }
}
```

- 콜백은 메인 스레드에서 온다. 화면이 이미 종료됐는지(`isFinishing()`/`isAdded()`) 확인하고 UI 를 바꾼다.
- 중복 클릭 방지: 요청 중에는 버튼을 비활성화한다.
- 로그인은 Firebase Auth 로 되어 있어야 한다(토큰은 SDK 가 자동으로 붙인다).
- 에뮬레이터 연결(개발 빌드에서만): `FirebaseFunctions.getInstance("asia-northeast3").useEmulator("10.0.2.2", 5001);`, `FirebaseAuth.getInstance().useEmulator("10.0.2.2", 9099);`

### 배포 중 발견·수정한 문제

1. **배포 환경 `app/no-app`(INTERNAL 500)** — 배포 환경에서는 firebase-functions 가 토큰 검증용 Admin 앱을 이름을 붙여 먼저 만든다. `getApps().length === 0` 검사로는 기본 앱을 만들지 않아 Firestore 접근이 실패했다. 기본 앱(`[DEFAULT]`) 존재 여부로 바꾸고 재현 테스트를 추가했다. 에뮬레이터에서는 재현되지 않는 문제였다.
2. **서버 비밀값 끝 CRLF** — 메모장 파일(`--data-file`)로 등록하면 키 끝에 `\r\n` 이 붙는다. 서버에서 BOM·앞뒤 공백·줄바꿈을 지우고, 가운데에 잘못된 문자가 있으면 값 없이 `AI_UNAVAILABLE` 로 처리한다.
3. **예상하지 못한 오류 로그 없음** — Callable 래퍼 밖에서 난 오류도 이름·코드·메시지(키 마스킹, 300자)를 `ai_callable_unexpected_error` 로 남기도록 했다.
