# BT-040 / Issue #40 — 알림 선호·요청 팝업 실제 연결

담당 D / P2. 선행 BT-039·008. BT-039 브랜치 기반에서 추가한 독립 커밋으로 관리한다.

## 확정 정책

- 메시지·요청·성사·공강·후기 작성·후기 수신의 OFF는 푸시만 억제하고 inbox 생성/이력은 유지한다.
- 요청 팝업은 독립 `popup` 스위치. 오늘 숨김은 서버의 Asia/Seoul 날짜에만 유효하다.
- 오늘 숨김은 자동 팝업만 막고 받은 요청의 수동 열기·수락·거절은 허용한다.
- 매칭 스위치와 공강 알림은 독립이다. 공강 시작 시 발생하며 푸시 여부는 availability 선호를 따른다.
- 처리 지연 시 공강 시작 후 2분까지만 푸시하며, 이후에는 원래 시작 시각으로 앱 내 이력만 남긴다. 전송 재시도에도 기한을 연장하지 않는다.
- 기본값은 기존 BT-008과 같이 message/request/popup=true, 나머지=false. 기존 기기 공용 Mock 값을 실제 계정의 설정으로 자동 이관하지 않는다.

## API·스키마

`notificationSettings/{uid}` 본인 읽기, 쓰기는 서버 전용이다.
필드: message/request/accepted/availability/reviewWrite/reviewReceived/popup(boolean), suppressedDate(빈 문자열 또는 한국 YYYY-MM-DD), updatedAt(Timestamp).

- `updateNotificationSettings({key,value})`: key는 위 boolean 키 또는 `suppressToday`, value는 boolean. UID·날짜를 클라이언트에서 받지 않는다. 서버 트랜잭션에서 한 필드만 갱신해 다른 기기/다른 스위치 변경을 덮지 않는다.
- `requestPopupPolicy({})`: 서버 날짜로 `{allowed,today}` 반환. popup OFF가 오늘 숨김 해제보다 우선한다. UI의 기기 시계가 자동 표시 권한을 결정하지 않는다.
- 팝업의 오늘 숨김 체크 상태도 위 서버 날짜를 사용한다. 단말 시계 조작으로 체크 표시/억제 판단이 달라지지 않게 한다.
- 두 함수 모두 검증된 학교 이메일의 토큰 UID를 사용. 다른 계정 지정·임의 날짜·알 수 없는 키는 거부한다.

## UI·재사용

- `NotificationSettingsActivity`: 기존 MaterialSwitch·구획·색상 유지. 원격 로딩 전 비활성화, 저장 중 중복 변경 차단, 실패 시 복원·재시도, onStop 리스너 해제.
- `NotificationSettingsRepository`: UID를 고정해 본인 문서를 관찰하고 늦은 이전 계정 응답을 버린다. Firebase 설정은 기기 공용 SharedPreferences를 읽지 않는다.
- `RequestPopupCoordinator`: 실제 공용 요청 저장소 + 원격 선호 + 서버 날짜 정책 확인 후 세션당 자동 팝업 한 번. 숨겨진 화면·화면 저장 이후·이미 처리된 요청에는 표시하지 않는다.
- 알림 목록의 요청 항목은 `RequestPopupNavigator`로 받은 요청을 기다린 뒤 직접 연다. 오늘 자동 표시를 껐어도 이 수동 진입은 허용하며, 이미 처리된 요청이면 안내만 표시한다.
- `MatchRequestDialog`/`FirebaseRequestPopupController`: 기존 팝업 레이아웃·체크박스·요약 컴포넌트 재사용. 공개 프로필만 조회하고 실제 요청 respond API 사용. 응답 대기 중 중복 수락/거절 차단, 취소·만료 상태 변경도 관찰한다.
- Mock 설정도 UID별 저장 공간으로 분리한다. 실제 수락 결과를 Mock 성공으로 대체하지 않는다.

- 설정 교차 계정 차단, 동시 필드 변경, 서버 KST 자정, 팝업 OFF 우선, 임의 UID·날짜 거부를 검사했다.
- Android `assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug` 성공, JVM 751개 통과.
- 보이는 Pixel 10 `NotificationSettingsDeviceTest`에서 로컬 Auth/Firestore/Functions를 통해 설정 저장·회전 복원, 서버 당일 숨김, 수동 팝업, 실제 요청 거절, 다른 계정 기본값을 확인했다.
- 수동 진입을 두 번 연속 호출해도 팝업은 하나만 표시됨을 확인했다. 화면 증거: [설정 복원](./screenshots/BT-040/01-settings-restored.png), [오늘 자동 숨김 중 수동 팝업](./screenshots/BT-040/02-popup-local.png). 기존 스위치·체크박스·시간 요약·닫기 버튼 스타일을 유지한다.
- BT-038·039·040 임시 통합 후 Node 24.22.3에서 서버 빌드·단위 267개(이전 293개 집계 정정)·Firestore/RTDB 통합 104개 통과, Storage 7개 skip. Android 빌드·lint·JVM 751개와 Pixel 10 설정 테스트 1개도 통합 APK에서 재통과했다. 검증 후 임시 병합은 되돌려 이슈별 브랜치를 유지했다.

- BT-039를 먼저 통합한 뒤 이 브랜치를 반영한다. BT-038과는 README/BT-012의 문서 삽입, 함수 export 목록, 인덱스 추가 위치가 겹친다. 양쪽 내용을 모두 보존해 통합 검증했으며 추후 PR 병합 때도 같은 조정이 필요하다.
- 운영 함수/Rules/인덱스 배포, 실제 두 기기 FCM 전송은 미실행. 후기 실제 작성·공개는 BT-044와 통합 검증 필요.
