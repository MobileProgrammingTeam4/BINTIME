# BT-044 / Issue #44 — 매칭 후기 작성·조회와 상대 후기 공개 조건

담당 E / P1. 선행 BT-033·BT-038·BT-010. 종료 스키마(`status`·`endReason`·`reviewEligible`)는 [BT-038](./BT-038.md)(#121), 후기 대상 선택은 [BT-035](./BT-035.md), 신고 연동은 [BT-051](./BT-051.md)(#131), 탈퇴 처리는 [BT-045](./BT-045.md)(#130)를 따른다.

## 1. 확정 사항

| 항목 | 기준 |
|---|---|
| 기준 식별자 | 개별 `matchId`. `chatRoomId` 로 후기 키를 만들지 않는다(BT-038 §5) |
| 건수 | **매칭·작성자당 1건.** 문서 ID `reviews/{matchId}_{authorUid}` 로 구조적으로 보장하고, 서버 트랜잭션이 중복·동시 제출을 막는다 |
| 작성 자격 | 참여자 · `status === "ENDED"` · **`reviewEligible === true`(BT-038 서버 확정 값)** · 상대 `accountDeletions/{uid}` 없음. 앱이 보낸 자격은 받지 않는다 |
| 시작 전 종료·탈퇴 종료 | `reviewEligible=false` 로 저장된다(시작 전 수동 종료, #130 `endReason=ACCOUNT_DELETED`). 서버는 `NOT_ELIGIBLE` 로 거부하고, 앱은 BT-035 정책대로 후기 대상에서 빼서 버튼을 숨긴다 |
| 매칭 뒤 상대 탈퇴 | 종료 뒤 상대가 탈퇴했으면(`accountDeletions/{상대 uid}`) 작성을 `PARTNER_DELETED` 로 거부한다 |
| 공개 조건 | **내 후기는 항상, 상대 후기는 내 후기가 있을 때만** 서버가 돌려준다. 내가 쓰기 전에는 상대 후기의 존재 여부도 알리지 않는다(LOCKED) |
| 수정·삭제 | 없음 |
| 한 줄 후기 | 앞뒤 공백 제거 후 0~100자, 비면 null. 연락처는 지우지 않는다(이미 채팅하는 상대, 팀 결정) |
| 알림 | BT-039(#122)의 `notificationOnReviewCreated` 가 `reviews/{id}` 생성 시 `matchId`·`authorUid`·`targetUid` 세 필드만 읽어 내용 없이 알린다. 필드 이름을 바꾸지 않는다 |
| 탈퇴자 후기 | **미정.** 탈퇴한 사용자가 쓰거나 받은 후기를 지울지·남길지는 B(김환님, #130)와 결정한다. 이번 구현은 지우지도 숨기지도 않는다 |

## 2. 저장 스키마 (서버 전용)

`reviews/{matchId}_{authorUid}`

| 필드 | 형식 |
|---|---|
| matchId | 64자리 소문자 hex |
| authorUid | 작성자 Auth UID(토큰) |
| targetUid | 상대 UID. 서버가 `matches.participantUids` 에서 정한다 |
| satisfaction | `BAD` · `GOOD` · `GREAT` (앱 `Satisfaction`) |
| keywords | 앱 `ReviewKeyword` enum 이름 배열(enum 순서, 중복 없음, 0~10개) |
| comment | 문자열(1~100자) 또는 null |
| createdAt | 서버 Timestamp |

**Rules: 바꾸지 않는다.** `firestore.rules` 에 `reviews` 규칙이 없어 앱은 읽기·쓰기 모두 거부된다(기본 거부). 쓰기와 읽기 모두 아래 Callable 만 한다. 인덱스도 필요 없다(문서 ID 로만 읽음).

## 3. Callable (asia-northeast3)

공통: 로그인·학교 이메일(`ALLOWED_EMAIL_SUFFIXES`) 확인 후 입력을 zod `strict` 로 검사한다. UID·상대 UID·자격 같은 필드를 보내면 `invalid-argument`. 오류 details 는 `{reason, requestId}`.

### `submitReview({matchId, satisfaction, keywords, comment})` → `{matchId, written: true}`

| 오류 | reason | 경우 |
|---|---|---|
| permission-denied | PERMISSION_DENIED | 비참여자·없는 매칭(존재 여부를 알리지 않음)·탈퇴 진행 중인 본인 |
| failed-precondition | ALREADY_REVIEWED | 이미 이 매칭에 후기를 씀(동시 제출 포함, 1건만 남음) |
| failed-precondition | NOT_ELIGIBLE | ENDED 아님·`reviewEligible !== true`(필드 없는 이전 ENDED 포함, backfill 없음) |
| failed-precondition | PARTNER_DELETED | `accountDeletions/{상대 uid}` 있음 |
| unavailable | RETRY_LATER | 예상하지 못한 오류(내용·UID 는 로그에 남기지 않음) |

### `getMatchReview({matchId})`

```text
{ matchId, partnerUid, canWrite,
  meetingDate, startMinute, endMinute,          // 확정 스냅샷(없으면 null)
  mine: ReviewView | null,
  received: { visibility: "LOCKED" | "NOT_YET" | "VISIBLE", review: ReviewView | null } }
ReviewView = { satisfaction, keywords, comment, createdAt(ms) }
```

- `canWrite` = 내 후기 없음 ∧ ENDED ∧ `reviewEligible === true` ∧ 상대 미탈퇴.
- 내 후기가 없으면 상대 후기가 있어도 `LOCKED`·`review: null`. 내 후기가 있고 상대가 안 썼으면 `NOT_YET`.
- 비참여자·없는 매칭은 permission-denied.

## 4. 앱

| 파일 | 내용 |
|---|---|
| `review/ReviewRepository` | `loadMatchReview(matchId)`·`submitReview(matchId, satisfaction, keywords, comment)`. 상대 UID 인자는 없앴다(서버가 정함) |
| `review/FunctionsReviewRepository`·`ReviewMapper`·`ReviewFailure` | Callable 호출·응답 매핑·오류 분류. 호출 중 계정이 바뀌면 결과를 버린다 |
| `review/ReviewRepositories` | Firebase 설정 시 Callable, 아니면 `MockReviewRepository` |
| `review/ReviewEntry` | 채팅 밖 진입점. 아래 5장 |
| `review/ReviewWriteActivity` | 제출 중 중복 클릭 방지. `ALREADY_REVIEWED` → 조회 화면, `NOT_ELIGIBLE`·`PARTNER_DELETED` → 안내 후 닫기, 일시 오류 → 입력 유지·재시도. "만나지 못했어요" 는 **개별 matchId** 로 `ReportActivity.intent(context, partner, matchId)` (BT-051 §4) |
| `review/ReviewDetailActivity` | LOCKED·NOT_YET·VISIBLE·오류 상태. LOCKED 이고 `canWrite` 면 "후기 남기기" 버튼, 쓸 수 없는 약속이면 "이 약속은 후기 대상이 아니에요" 안내만 |
| `chat/ChatRoomActivity` | Firebase "준비 중" 분기 제거. 후기 대상(`MatchAppointmentPolicy.targets(REVIEW)`)마다 `getMatchReview` 로 내 작성 여부를 읽어 남기기/보기 버튼을 정한다. 방 갱신(새 메시지)마다는 아직 모르는 약속만, 화면 복귀 때는 전부 다시 묻는다 |

후기와 신고는 서로 독립이다. 신고했다고 후기를 막거나 공개 조건을 바꾸지 않는다(BT-051 §4).

## 5. D 화면 연동 (요청 사항)

완료된 매칭 탭(`request/RequestTabsController`)과 알림 목록(`notification/NotificationListFragment`)은 D 파일이라 이번 PR 에서 고치지 않았다. 지금은 두 곳 모두 `request_review_pending` 안내만 띄운다. 아래 한 줄로 바꾸면 된다.

```java
// 완료된 매칭 카드: 이미 가진 상대 정보가 있으면 넘기고, 없으면 null
ReviewEntry.open(activity, matchId, partnerSummaryOrNull);
// 알림(reviewWrite·reviewReceived): notification 의 matchId 를 그대로
ReviewEntry.open(activity, notificationReviewMatchId, null);
```

- 서버 `getMatchReview` 로 내 후기가 있으면 조회, 쓸 수 있으면 작성 화면을 연다. 대상이 아니면 "이 매칭에는 후기를 남길 수 없어요." 안내만 띄운다. 자격 판단은 앱이 하지 않는다.
- `partner` 가 null 이면 `publicProfiles` 에서 닉네임·요약을 읽고(B 의 `ProfileRepository.getPublicProfile`), 시간 박스는 매칭 스냅샷으로 만든다. 프로필을 못 읽으면 기본 이름("상대")으로 연다.
- 같은 약속을 연속으로 눌러도 화면은 한 번만 열린다.
