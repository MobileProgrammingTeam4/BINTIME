- `MockRequestRepository`: 생성 시 PENDING, 자기 자신/유효하지 않은 시간/중복 신청을 검사한다. 생성한 날짜·시작/종료 분은 final이며 상태 변경으로 갱신하지 않는다. 시연 시드와 실제 데이터를 섞지 않는다.
- 기존 `MatchSummaryBinder`, `item_request_card`, `view_time_overlap`, `ConfirmDialog`, `FeedbackDialog`, `StateView`를 재사용한다. Figma 레이아웃 변경은 없다.

- 현재 `MockMatchRepository` 후보만 존재하므로 Firebase 모드에서는 실제 신청 성공을 표시하지 않는다. 기존 수락/거절의 동기 `respond`는 Mock 시연만 지원하며 실제 연결은 BT-031 범위다.

## Callable API

리전 `asia-northeast3`. `createMatchRequest({ candidateId, clientRequestId })`.
인증 UID는 Callable 토큰에서만 읽는다. 요청 본문에 UID/목적/날짜/시간을 추가하면 입력 오류다.

`candidateId`는 길이 1~200의 불투명 식별자(`A-Z a-z 0-9 : _ -`), `clientRequestId`는 UUID다.
응답은 요청 문서 ID `id`, 참여자·목적·시간 스냅샷·상태, `createdAtMillis`/`updatedAtMillis`다.
오류는 `HttpsError`와 `details.{reason,retryable,requestId}`로 반환하고 내부 예외나 개인정보를 노출하지 않는다.

### BT-017에 전달할 연결 계약 (A/SM 검토 필요)

`CandidateResolver.resolve(transaction, fromUid, candidateId, now)`는 **서버 내부 전용**이다.
후보 저장 위치·발급 방식은 이 PR에서 새 컬렉션으로 정하지 않는다. A가 적격 후보를 해석하는 어댑터를 연결한다.
동일 Firestore 트랜잭션에서 양측 스위치 ON, 최신 revision, 최소 겹침(60/90/120/150/180), 목적·차단·기존 매칭 충돌을 재검사해야 한다.
반환 값은 `{toUid,purpose,meetingDate,startMinute,endMinute}`이며 검사가 끝난 실제 교집합이어야 한다. 날짜는 KST `YYYY-MM-DD`, 분은 자정 기준 정수, 반열린 구간이다.
서비스도 자기 자신·잘못된 날짜/시간·60분 미만·이미 종료된 공강을 다시 거절한다.

현재 배포용 기본 어댑터는 `SEARCH_NOT_CONNECTED`로 실패한다. Gemini 점수나 클라이언트 시간, 테스트 후보로 대체하지 않는다.
테스트에서만 검증 완료 후보를 대신하는 어댑터를 주입한다. A/C/B의 스키마와 정책을 임의로 확정하지 않았다.

## Firestore 계약

`matchRequests/{sha256([authUid,clientRequestId])}`:

| 필드 | 내용 |
|---|---|
| `fromUid`, `toUid` | 토큰 사용자, 서버가 해석한 후보 |
| `candidateId` | 서버 후보 식별자, 멱등 키 재사용 충돌 검사 |
| `purpose` | 생성 당시 목적 |
| `meetingDate`, `dayOfWeek` | 날짜, 월=1~일=7 |
| `startMinute`, `endMinute`, `overlapMinutes` | 변경하지 않는 시간 스냅샷, 마지막 값은 종료-시작 |
| `status` | 최초 `PENDING` |
| `createdAt`, `updatedAt` | 서버 Timestamp |

`matchRequestGuards/{sha256([fromUid,toUid])}`는 서버 전용 중복 잠금이다.
필드는 `fromUid`, `toUid`, `pendingRequestId`. 같은 방향의 한 쌍에는 PENDING 한 건만 허용한다.
잠금 문서와 요청을 한 트랜잭션으로 생성한다. 다른 UUID를 사용한 동시 클릭도 중복을 막는다.
동일 UUID 재시도는 기존 요청을 반환한다. 시간표/후보가 나중에 바뀌어도 기존 스냅샷을 다시 계산하지 않는다.
취소된 뒤 새 UUID로 재신청할 수 있으며 기존 요청 문서는 남긴다.

`firestore.rules`는 요청 참여자의 읽기만 허용하고 클라이언트 생성·수정·삭제 및 잠금 접근을 거절한다.
현재 저장소에 기존 Rules가 없으므로 요청 경로만 추가했다. 다른 영역의 허용 규칙이나 운영 배포는 이번 범위가 아니다.
실제 배포 전 B/A/SM이 전체 Rules와 통합 검토해야 한다.
