## 구현 계획

1. **서버 공통 보호 기반부터 구현한다.** 기존 `requests/`에 UID별 한도/직접 취소 제한과 양방향 쌍 보호를 추가한다. 한도·충돌을 지키는 공통 사용자 단위 조정 지점을 생성·취소·수락·거절·자동 정리가 공유하도록 설계한다. 단순 화면 개수나 서로 다른 요청 문서만으로 동시성을 보호하지 않는다.
2. **생성·직접 취소를 보완한다.** 기존 UUID 멱등 결과 확인을 한도·cooldown 판정보다 먼저 수행해 이미 성공한 요청의 재시도를 막지 않는다. 동일 취소 재시도는 60초를 연장하지 않는다. 실제 새 직접 취소의 성공만 제한 시각을 갱신한다. 실패·자동 정리는 갱신하지 않는다.
3. **A의 검색과 재검증을 연결한다.** `functions/src/matching/search.ts`의 검색 후보에서 수신 상한과 받은 요청의 발신자를 제외한다. 검색 이후 바뀐 한도·관계는 생성 API에서 재검증한다. 기존 ON/OFF·공강 없음·결과 없음 상태와 최소 겹침·목적·차단 판정은 보존한다.
4. **실제 수락/거절 Callable을 구현한다.** 서버 토큰과 학교 이메일을 확인하고 requestId·허용된 동작만 받는다. 기존 취소와 같은 오류 형식·리전을 재사용한다. 비참여자, 발신자, 종결된 요청, 만료, 차단·계정 불가를 처리한다. 구체적인 입력 스키마와 오류 reason 이름은 구현 PR에서 계약으로 확정한다.
5. **수락과 충돌 방지에 필요한 매칭 생성을 같은 Firestore 트랜잭션에 둔다.** `ACCEPTED`만 기록하고 확정 매칭을 나중에 만들어 충돌 창이 생기지 않게 한다. `matchId = requestId`, 참여자·purpose·날짜·요일·시작/종료·겹침은 원본 요청에서 한 번 복사하고 `ACTIVE`, 초기 `chatReady=false`로 둔다. 이 공통 생성 경로를 BT-033이 그대로 사용해 채팅 연계를 완성하며 두 이슈가 서로 다른 매칭 생성 로직을 만들지 않는다.
6. **Android를 비동기 실제 경로에 연결한다.** `RequestRepository`, `FirebaseRequestRepository`, `MockRequestRepository`, `RequestTabsController`와 공통 신청 버튼에 성공·로딩·오류·재시도·중복 클릭 방지를 적용한다. 기존 `ConfirmDialog`, `FeedbackDialog`, `MatchAcceptedActivity`, 카드·빈 상태를 재사용한다. 실제 상대 정보는 기존 공개 프로필 API와 사진 로더를 사용하고 Mock 이름으로 대체하지 않는다.
