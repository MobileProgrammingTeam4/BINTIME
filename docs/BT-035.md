# BT-035 / Issue #35 — 채팅 상단 시간·여러 약속 표시 인수인계

담당 E / P0. [실제 이슈 #35](https://github.com/MobileProgrammingTeam4/BINTIME/issues/35), 선행 BT-033·034. 방 식별·복구·약속 선택 창 API는 [BT-034](./BT-034.md)를 먼저 확인한다. 2026-11-17 로컬 구현 기준이며 실제 두 계정 통합 완료를 뜻하지 않는다.

## 1. 시간·대표 약속 정책

| 항목 | 기준 |
|---|---|
| 원본 | matches/{matchId} 확정 날짜·시작/종료. 현재 시간표·후보·최근 메시지 시각으로 대체 금지 |
| 대표 | 현재 진행 중 ACTIVE 우선, 없으면 가장 가까운 미래 ACTIVE |
| 추가 건수 | 대표를 제외한 미종료 약속만 ‘외 N건’. 종료된 과거 약속 제외 |
| 경계 | KST [startMinute, endMinute). 종료 시각 이상은 대표/추가 건수에서 제외. 날짜가 다른 분만 직접 비교 금지 |
| 미래 약속 | ‘예정’ 표시. 시작 전을 이미 만남 중인 것으로 표시하지 않음 |
| 남은 시간 | 대표 약속 종료 시각 기준, 음수 방지 |
| 서버 종료 지연 | 종료 시각이 지났는데 matches.status가 아직 ACTIVE면 마지막으로 끝난 ACTIVE 약속 카드를 유지하고 남은 시간 0:00:00(결정 A, 2026-11-20). 종료 배너는 서버가 ENDED로 바꾼 뒤에만. 새 문구 없음, Android는 status를 쓰지 않음 |
| 전부 ENDED | 종료 안내. 양측 잔류 방은 계속 대화 가능 |
| 이전 대화 | 상단 기존 종료·후기 컴포넌트. 마지막 말풍선 아래 회색·중앙·둥근 나가기 안내, 기존 MessageComposer 비활성 상태 |
| 후기 버튼 | 후기 대상 중 하나라도 미작성은 ‘매칭 후기 남기기’, 전부 작성은 ‘매칭 후기 보기’. 대상이 없으면 숨김. 시작 전 종료·자격 미확정 약속은 집계에서 제외 |
| 종료·후기 | 상단 대표를 자동 선택하지 않고 개별 matchId 선택. 예정 약속 종료 허용, 시작 전 종료는 후기 영구 제외 |

ACTIVE 약속이 하나라도 남은 방의 나가기 금지를 BT-043과 공유한다. 실제 종료와 후기 자격은 BT-038/044 서버가 검증한다.

## 2. 실제 제공 코드

Android 공통 경로: app/src/main/java/com/team4/bintime/.

| 코드 | 사용 방법 |
|---|---|
| request/MatchAppointment | startAtMillis()/endAtMillis()가 Asia/Seoul 날짜와 1440분 경계 처리 |
| request/MatchAppointmentPolicy | representative(all, now), additionalCount(all, now), targets(all, action), allReviewsWritten(all). 선택·후기 버튼 정책을 복제하지 않고 재사용 |
| chat/FirestoreMatchInfoSource | UID 참여·chatRoomId 조건으로 불변 약속 목록 구독. ChatRepositories에 실제 소스 연결 |
| chat/ChatRoom.appointments | 연결 약속 목록. ChatRoom.matchId는 호환 API의 방 키이므로 개별 ID와 구분 |
| chat/ChatRoomActivity.bindMatchInfo() | 매번 대표 재선택 후 기존 ChatTimeFormatter·시간 카드 재사용. ‘외 N건’·예정 표시 |
| chat/ChatRepository.nowMillis() | 표시용 시각. Firebase는 RTDB .info/serverTimeOffset 보정(chat/ServerClock), Mock은 주입 Clock |
| chat/ChatAppointmentDisplay.pick(all, now) | 상단 카드 약속. MatchAppointmentPolicy.representative를 먼저 쓰고, 없을 때만 종료 시각이 지난 ACTIVE 중 가장 늦게 끝난 약속(서버 종료 지연). FirestoreMatchInfoSource 방 대표 시간도 같은 기준 |
| chat/ServerClock | 보정 값 받기 전 0, 숫자가 아닌 값 무시, 구독 취소 시 마지막 값 유지(0으로 되돌리지 않음) |
| ChatRepository.retryFailedSources() | ChatRoomActivity.onResume에서 호출. 오류로 끊긴 매칭 스냅샷 구독만 한 번 다시 연다(ChatRoomsCombiner.retryFailedMatches). 자동 반복 없음, 상대 프로필은 다시 열지 않음 |
| chat/ChatRoomActivity | RESUMED 중 1초 갱신, onPause/onDestroy 타이머 해제, 복귀 시 대표·후기 상태 재계산 |
| request/MatchSelectionSheet | BT-034 §5의 Fragment Result와 공개 API로 종료/후기 선택. 최신 목록·서버에서 다시 검증 |
| common/TimeMatchViews.bindCompact | 기존 view_time_overlap 재사용. 날짜·시간·겹침 시간·상태로 목록 구성, 목적 문구 생략 |
| chat/ChatComposer.bind(view, readOnly, ready, sending) | 기존 입력창 재사용. 보관은 ‘기록 열람만 가능해요’, 준비 중은 ‘채팅방 준비 중…’ hint와 입력·전송 비활성. 기존 3인자 API도 유지 |

서버 시각 보정은 화면용 추정값이다. 카운트다운 0만 보고 Android가 matches.status를 쓰지 않는다. 자동/수동 종료·reviewEligible 확정은 BT-038 경로다.

FirestoreMatchInfoSource도 MatchInfoSource.useClock을 통해 FirebaseChatRepository.nowMillis를 주입받아 대표 약속을 계산한다. 단말 시각만 별도로 사용하는 경로를 없앴다. 방 단위 준비 상태는 userChatRooms.chatReady가 우선이며, 필드 없는 이전 방만 매칭 링크 값을 호환용으로 사용한다.

## 3. E가 이어서 검증할 경계

- 소스 100건 초과는 오류다. 일부만 읽고 잘못된 전체 건수를 표시하지 않는다. 과거 약속 페이지 조회·명시적 오류/재시도는 BT-034에서 확장한다.
- Firestore/RTDB listener는 화면 종료 시 해제하고 오래된 결과가 새 방을 덮지 않게 한다.
- ENDED 이벤트를 방 목록 status에 반영할 때 다른 ACTIVE 약속을 함께 집계한다. 과거 한 건 종료로 방 전체를 종료 표시하지 않는다.
- 단말 시계 오차·보정 값 수신 전후, 장시간 백그라운드, KST 자정, 인접 약속 경계·서버 종료 지연을 실제 환경에서 확인한다. → 2026-11-20 확인(5장). KST 자정은 JVM 테스트로만 확인했다.
- reviewWritten은 실제 본인 후기 상태로 채운다. 현재 Firebase 모드는 Mock 후기 저장을 호출하지 않는다. 실제 endMatch/leaveRoom은 BT-038/043 연결 전 실패한다.
- 공개 프로필·BT-034 안읽음·실제 방 연결과 함께 두 계정 전송, 시간표 변경 후 원래 스냅샷 보존을 검증한다.

## 5. BT-035 후속 구현과 실서버 E2E (2026-11-20)

### 구현
- **서버 종료 지연(결정 A)**: `chat/ChatAppointmentDisplay`. D 소유 `request/MatchAppointmentPolicy`는 바꾸지 않고 chat/ helper에서 기존 대표 선택 뒤 빈 구간만 채운다. 서버가 ENDED로 바꾼 약속은 더 늦게 끝나도 후보가 아니다.
- **서버 시각 보정 유지**: `chat/ServerClock`. 예전에는 `.info/serverTimeOffset` 구독이 취소되면 0으로 되돌렸다.
- **복귀 시 재구독**: Firestore 매칭 구독이 오류(권한·잘못된 데이터·100건 초과)로 끊기면 SDK가 같은 리스너를 다시 부르지 않는다. 채팅방 복귀 때 끊긴 것만 한 번 다시 연다.
- 단위 테스트: `ChatAppointmentDisplayTest` 9(종료 경계 [start,end), 붙은 약속, 시각 점프 앞뒤, UTC 단말의 KST 자정·어제 포함), `ServerClockTest` 5, `ChatRoomsCombinerTest` 재구독 6. 기기 테스트 `AppointmentSelectionDeviceTest.overdueActiveKeepsLastCardWithZeroRemaining`(Mock): [종료 지연 카드](./screenshots/BT-035/01-overdue-zero-remaining.png).

### 실서버 E2E
운영 `bintime-mobile`, 앱 `feature/chat-BT-035`(`d0b59e5`, develop `7dd7090` 포함), 함수는 같은 날 develop `7dd7090`으로 배포한 ensureMatchChat·chatOnMatchCreated·searchMatches. 기기 A = API 36.1 google_apis(root, 시계 조작용), 기기 B = API 37(단말 시간대 UTC). 테스트 계정 3개(학교 이메일 +bt1~3, 닉네임 E2EA·E2EB·E2EC). 약속 A–B 21:27~22:30, A–C 22:30~24:00(붙은 약속). 운영 데이터는 읽기만 했다.

| 확인 | 결과 |
|---|---|

| 시계 −10분으로 앱 새로 시작 | 통과. 처음부터 다른 기기와 같은 남은 시간(0:54:21 대 0:54:19, 읽는 순서 차이) — [화면](./screenshots/BT-035/03-e2e-clock-minus10.png) |

남은 한계와 후속:
- 실행 중 단말 시계 변경은 RTDB 재연결 전까지 반영되지 않는다(SDK가 연결 시 offset 계산). 표시 전용이고 종료 판정에 쓰지 않아 이번에는 두고, 필요하면 `ACTION_TIME_CHANGED` 수신 시 재연결을 후속 검토한다.
- 서버 종료 이후 표시(ENDED 전환·종료 배너·후기)는 BT-038 자동 종료 배포 뒤 BT-043/BT-060에서 확인한다.
- KST 자정을 넘는 실제 약속은 실서버로 보지 않았다(JVM 테스트로 확인).
