# BT-035 / Issue #35 — 채팅 상단 매칭 시간·남은 시간·복귀 갱신 인수인계

담당 E / P0. 선행 BT-033·034. [실제 이슈 #35](https://github.com/MobileProgrammingTeam4/BINTIME/issues/35).
2026-11-17 기준 정책과 연결 계획이다. 실제 기능 완성을 뜻하지 않는다. 방 연결·약속 선택 창 위치는 [BT-034](./BT-034.md), 확정 스냅샷은 [BT-033](./BT-033.md)를 함께 본다.

## 요구사항과 추가 승인 정책

| 항목 | 적용 기준 |
|---|---|
| 시간 원본 | Firestore 확정 매칭 스냅샷. 현재 시간표·검색 후보·RTDB 마지막 메시지 시각으로 대체 금지 |
| 상단 대표 약속 | 현재 진행 중 우선. 없으면 가장 가까운 예정 약속 |
| 여러 약속 | 대표 약속 뒤 ‘외 N건’ 표시. N은 대표를 제외한 미종료 약속 수이며 종료된 과거 약속은 세지 않음 |
| 전부 종료 | 매칭 종료 상태 안내. 둘 다 방에 남았으면 채팅은 계속 가능 |
| 시간 경계 | KST meetingDate와 [startMinute, endMinute). 13~14시가 끝나고 14~15시가 시작하면 대표 대상 전환 |
| 남은 시간 | 선택된 약속 종료 시각 기준. 시작 전에는 예정임을 구분하여 현재 만남이 진행 중인 것으로 표시하지 않음 |
| 화면 복귀 | 최신 매칭 목록/종료 상태를 다시 확인하고 현재 서버 기준 시간으로 대표 약속·추가 건수·남은 시간 재계산 |
| 종료 처리 | 카운트다운 0을 근거로 Android가 DB를 직접 변경하지 않음. 실제 종료는 BT-038 서버 경로 |
| 이전 대화 보관 방 | ‘이전 대화’·읽기 전용 표시를 우선하고 진행 중 약속이 있는 것처럼 카운트다운을 표시하지 않음 |

## E 담당자 연결 지점

| 현재 코드 | 필요한 연결 |
|---|---|
| `ChatRepositories`의 `MatchInfoSource.UNAVAILABLE` | BT-034 실제 매칭/방 참조를 통해 해당 방의 연결 매칭들을 읽는 소스로 교체 |
| `ChatRoom`의 단일 매칭 시간·상태 | 대표 약속 표시용 정보와 실제 방 ID를 구분. 방 재사용 시 이전 시간 덮어쓰기로 구현하지 않음 |
| `ChatRoomActivity` 시간 카드·주기 갱신 | 공통 약속 선택 정책으로 매번 대표·외 N건 계산. 시간 경계에서도 리스너 새 이벤트 없이 표시 전환 |
| `ChatTimeFormatter` | 확정 날짜·시작/종료를 받아 표현. 선택 정책과 분리하고 미래/경계/자정 테스트 유지 |
| 종료·후기 버튼 | BT-034의 약속 선택 창 결과인 개별 matchId로 이동. 상단 대표를 자동으로 종료/후기 대상으로 확정하지 않음 |

공통 약속 모델/선택 정책/선택 창은 BT-034 문서의 예정 경로를 사용하며 실제 구현 후 호출 코드와 Bundle 키를 갱신한다. E가 같은 선택 로직을 별도로 복제하지 않도록 인계한다.

## 검증할 예외

| 상황 | 기대 결과 |
|---|---|
| 현재 진행 1건 + 미래 2건 | 현재 약속과 ‘외 2건’ |
| 미래 약속 2건 | 가장 이른 약속과 ‘외 1건’, 예정 표시 |
| 첫 약속 종료 경계 통과 | 다음 미종료 약속으로 전환, 남은 시간 음수 미표시 |
| 선택된 약속만 수동 종료 | 다른 약속으로 대표 전환, 방과 다른 약속 유지 |
| 시작 전 수동 종료 | 대표/추가 건수에서 제외, 종료 서버 판정에 따라 후기 자격 없음 |
| 전부 종료·양측 잔류 | 종료 안내·추가 건수 없음, 채팅은 유지 |
| 앱 백그라운드에서 여러 약속 변경 | 복귀 시 최신 목록으로 계산. 과거 타이머 값만 이어 쓰지 않음 |
| 다른 날짜·KST 자정·단말 시계 오차 | 서버 기준 스냅샷과 시간 보정에 따라 표시. 정확한 서버 시간 보정 연결은 E 구현에서 검증 |
| 리스너 지연·화면 종료 후 콜백 | 오래된 결과로 대표/방을 덮지 않고 생명주기 종료 후 갱신하지 않음 |

실제 변경·검증 기록은 구현 후 추가한다. Mock UI 성공만으로 BT-035 완료로 보고하지 않으며 BT-033/034 실제 매칭 데이터와 시간 일치가 완료 게이트다.
