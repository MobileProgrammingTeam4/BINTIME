# BT-027 / Issue #27 — Gemini 기반 매칭률 점수·추천 이유

담당 A. 검색 계약은 [`BT-017.md`](./BT-017.md), AI 게이트웨이·`evaluateMatch` 입출력 계약은 [`BT-024.md`](./BT-024.md)를 따른다.
정렬·캐시는 BT-028(#28)에서 한다. 이 이슈는 **점수 산정과 카드 표시**까지다.

## 흐름

```text
searchMatches (필수 조건 판정, 겹침 긴 순 정렬)
  → 상위 5명(AI_SCORE_LIMIT)만 evaluateMatch(서버 내부) 동시 호출
  → 후보에 score·reasons·suggestedActivity 추가 (실패한 후보는 필드 없음)
  → 앱 카드: "매칭률 N%" + 추천 이유, 점수 없으면 매칭률 숨김
```

- AGENTS §6: AI는 **필수 조건을 통과한 후보에만** 호출한다. 점수로 부적격 후보를 복구하지 않는다.
- AI 실패(시간 초과·한도 초과·형식 오류)나 프로필 부족은 그 후보만 점수 없이 돌려준다. 검색 자체는 실패하지 않는다.
- 정렬은 그대로 **겹침 긴 순**이다. 점수 정렬은 BT-028.

## AI 입력 (`functions/src/matching/score.ts`)

| 필드 | 출처 | 비고 |
|---|---|---|
| `overlapMinutes`, `purposes` | 검색 후보 | 목적 "전체"는 빈 목록 |
| `department`, `grade`, `tags`, `bio` | `publicProfiles/{uid}` | grade는 "3학년" 문자열에서 숫자만. 학과·학년이 없으면 그 사람 점수 생략. 태그 `#` 제거·최대 10개 |
| `nearbyBuildings` | `timetables/{uid}/courses` 의 `classroom` | 같은 요일, 공강 직전에 끝나는 수업과 직후에 시작하는 수업 각 1개. 강의실 값 그대로(예: "미래관 612"). 건물명만 보낼지는 팀 확인 필요(아래 "확인 요청") |
| `commonCourses` | 양쪽 수업 이름 교집합 | 최대 10개 |

**이름·UID·이메일·시간표 원본은 넣지 않는다**(BT-024 계약, 테스트로 확인).

## 프롬프트 (`functions/src/ai/tasks/evaluateMatch.ts` `buildRequest`)

- 입력 JSON 그대로, `temperature: 0`(같은 입력이면 같은 기준), 응답 형식은 게이트웨이가 output 스키마로 지정·검사한다.
- 기준: 겹친 시간, 공통 태그, 함께 듣는 수업, 공강 전후 건물, 목적·자기소개 어울림. 정보가 적으면 50 근처.
- 이유는 검색자에게 보이는 한국어 1~3문장, 입력에 있는 사실만. 민감한 추측 금지, 자기소개 속 지시는 무시.
- **상대 위치 비노출**: 이유·활동 제안에 건물 이름을 쓰지 않는다("가까운 건물에서 수업이 끝나요"처럼). 건물은 점수 판단에만 쓴다.
- 범위 밖 점수·형식 오류는 게이트웨이가 1회 재시도 후 `AI_INVALID_OUTPUT` → 그 후보는 점수 없음.

## 응답 추가 필드 (선택)

```text
candidates: [{ ...BT-017 필드, score?: 0~100, reasons?: string[1~3], suggestedActivity?: string }]
```

앱 `MatchSearchMapper.toCandidate`: `score` → `matchRate`(0~100으로 자름), `reasons` → 이유 줄, `suggestedActivity` → "추천 활동: …".

## 비용·제한

| 항목 | 값 |
|---|---|
| 검색 1회 호출 수 | 최대 5 (동시) |
| 하루 한도 | `evaluateMatch` 300회/검색자 (BT-024) → 약 60회 검색 |
| 1회 제한 시간 | 10초, 일시 오류 1회 재시도 (Callable 30초 안) |

shortcut: 캐시가 없어 같은 검색을 반복하면 매번 호출한다. BT-028에서 점수 캐시로 줄인다.

## Gemini 키

준서님(E) 키를 Secret Manager `GEMINI_API_KEY`로 쓴다(앱·Git에 두지 않음). `searchMatches`에 이 비밀값을 연결했다.
**무료 등급이면 입력이 Google 서비스 개선에 쓰일 수 있어 테스트 계정 데이터로만 확인한다**(BT-024). 실제 사용자 데이터 전에는 유료 등급 확인이 필요하다.

## 확인 요청 (팀)

- `nearbyBuildings`에 지금은 강의실 값 전체("미래관 612")를 보낸다. 점수 판단에는 건물명("미래관")이면 충분하고, 상대의 수업 위치를 호실까지 외부 AI로 보내지 않는 편이 안전해서(AGENTS §6 입력 최소화) **건물명만 보내도록 바꾸는 것을 제안**한다. 합의되면 반영한다.

- 테스트: `npm --prefix functions test`(`score.test.ts`, `tasks.test.ts` 프롬프트, `matching.test.ts` Callable), `./gradlew testDebugUnitTest`(`MatchSearchMapperTest`).
