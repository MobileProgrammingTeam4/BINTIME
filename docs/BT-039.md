# BT-039 / Issue #39 — 실제 알림 목록·FCM·이벤트 연결

담당 D / P1. 선행 BT-008·020·033. 설정은 BT-040, 종료·후기는 BT-038·044와 연계한다.

## 확정 동작

- 알림 OFF는 해당 종류의 푸시만 막고 앱 내 알림 이력은 유지한다. 메시지·요청은 기본 ON, 성사·공강·후기 작성·후기 수신은 기존 설정 UI와 같이 기본 OFF다. 요청 팝업은 별도 설정이다.
- 공강 시작 시 알림. 매칭 스위치와 무관하다. 저장된 availability/timetable revision·정규화된 슬롯을 재검사한다.
- 후기 대상 매칭 종료 시 참여자별 작성 안내, 상대 작성 완료 시 수신 안내. 알림에 후기 내용·만족도·태그를 넣지 않는다.
- 과거 시간표 수정으로 기존 약속·알림을 재작성하지 않는다. 이미 처리된 요청의 지연된 생성 이벤트는 팝업을 다시 만들지 않는다.

알림 설정 화면에서 Android 13 이상 OS 알림 권한을 한 번 요청한다. 거부해도 앱 내 알림은 이용한다.
Firebase SDK는 기존 BoM을 유지하고 Messaging 모듈만 추가한다. Mock 화면은 기존 목업을 유지한다.

## 데이터·권한 계약

- `notifications/{uid}/items/{sha256(uid+source)}`: type, targetId, 선택 matchId/requestId/actorUid, 일반 title, createdAt, readAt. 본인 읽기 및 readAt=서버 시각 갱신만 허용. 생성·대상 변경·삭제는 서버 전용.
- `notificationDevices/{sha256(token)}`: uid, token, updatedAt. 앱 직접 읽기·쓰기 금지. `registerNotificationDevice({token, remove?})`가 토큰 UID로 등록/본인 해제한다. 같은 토큰을 새 계정에 등록하면 현재 UID로 귀속한다.
- `notificationPushJobs/{notificationId}`: uid, notificationId, status, attempts, nextAttemptAt, createdAt. 앱 접근 금지.
- `availabilityNotificationJobs/{uid}`: dueAt, meetingDate, startMinute, sourceRevision. 앱 접근 금지.
- `notificationSettings/{uid}`: 본인 읽기, 설정 변경 Callable은 BT-040에서 제공.

FCM payload는 수신 UID·알림 ID·종류·일반 제목/대상 ID만 포함한다. 대화 본문·후기 내용·이메일·토큰은 포함하지 않는다.
로그아웃 시 OS에 표시된 알림을 정리하며, 로그인 UID가 payload와 다르면 표시/탭 이동을 거부한다.

## 전송 실패·비용

- 업무 상태 변경 트랜잭션 안에서 FCM을 보내지 않는다. 푸시 실패로 매칭 수락·채팅·inbox를 되돌리지 않는다.
- Firestore 이벤트는 멱등 키로 재시도하며 1시간 이상 지난 이벤트는 새 알림으로 재처리하지 않는다. 메시지 푸시는 5분이 지난 이벤트를 버린다.
- FCM 모호한 응답/부분 성공에서 네트워크상 정확히 한 번 전송을 보장하지 않는다. 앱 알림 tag 및 inbox 키는 동일하게 유지한다.
- 스케줄은 코드만 준비. 배포 승인 전 Scheduler·유료 설정은 바꾸지 않는다. BT-038 자동 종료 작업과 별도로 유지보수 작업 1개가 추가되는 구성이다. 실행당 공강 20개·푸시 복구 20개 제한.
- 공강 알림은 시작 후 2분까지만 푸시하며 재시도에도 같은 원래 기한을 적용한다. 더 늦으면 원래 시작 시각의 앱 내 이력만 남긴다(2026-11-24 사용자 확정). 다음 공강은 다시 예약한다.
- Storage·운영 데이터·비밀 키 변경 없음. Rules는 최소 권한의 검수 대상 초안이며 배포 전 담당자 리뷰와 실제 권한 확인이 필요하다.

## BT-044 인수인계

`notificationOnReviewCreated`가 `reviews/{reviewId}`의 `matchId/authorUid/targetUid`를 사용한다.
이는 기존 Android Review 모델 필드와 같다. E는 실제 저장 계약을 확정할 때 이 세 필드를 유지하거나 D와 함께 어댑터를 변경한다.
서버가 참여자·ENDED·reviewEligible=true를 확인하고 본인 후기는 본인에게 수신 알림을 보내지 않는다.
`notificationReviewMatchId`를 채팅방 Intent에 전달한다. E는 후기 실제 API 연결 시 선택한 개별 매칭으로 진입하도록 연결한다.
현재 후기 저장/조회 화면은 Firebase 모드에서 Mock으로 열지 않는다. 실제 후기 작성·공개는 BT-044 완료 후 통합 확인 대상이다.

### 후속 실기기 검증

배포는 별도 승인 후 진행한다. 검증된 학교 계정 두 개와 서로 다른 기기에서 요청·수락·새 메시지 이벤트별 알림 수신자/이동 화면을 확인한다.
종류별 OFF·OS 권한 거부에서도 앱 이력이 남는지, 로그아웃/다른 계정 로그인 후 이전 UID 알림이 보이지 않는지 확인한다.
공강은 매칭 스위치 OFF에서도 설정 ON이면 시작 시 통지하고, 시작 후 2분을 지난 재시도는 푸시 없이 원래 시각의 이력만 남는지 확인한다.
이 문서의 FCM 테스트는 가짜 전송기이며 실제 FCM·자동 RTDB 트리거 전달 성공을 뜻하지 않는다.

로컬 가짜 FCM 전송과 실기기 실제 푸시는 구분한다.
운영 함수·인덱스·Rules 배포, 실제 두 기기 FCM 발송은 미실행이다.
