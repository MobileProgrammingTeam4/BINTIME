# BT-020 / Issue #20 — 보낸·받은 요청 실시간 조회·취소

담당 D. `feature/request-BT-019`의 생성 계약을 기반으로 `feature/request-BT-020`에서 작업했다.
두 브랜치의 PR 대상은 develop이며 BT-019를 먼저 통합한다. BT-020은 BT-019 커밋을 포함하므로 선행 PR 병합 전에는 누적 변경이 보인다. 이슈가 일부 구현된 단계이므로 PR은 `Related #19` / `Related #20`으로 연결하고 자동 종료하지 않는다. Firebase 배포는 이번 범위에 포함하지 않는다.
이번 합의 범위는 계약·Mock·Firebase Emulator까지다. 실제 BT-017 검색과 운영 2계정 검증 전에는 #19/#20 전체 완료로 판정하지 않는다.

## 조회·화면 계약

- `FirebaseRequestRepository`가 `matchRequests`를 `fromUid == authUid`, `toUid == authUid`로 각각 조회하고 `createdAt DESC`로 정렬한다.
- 참여자별 문서를 메모리에서 합쳐 PENDING 발신/수신과 ACCEPTED 목록으로 표시한다. 취소·거절된 문서는 보낸/받은 대기 목록에서 사라지지만 서버 원본은 보존한다.
- `RequestTabsController`가 View Lifecycle STARTED에서 구독하고 STOPPED에서 해제한다. 마지막 구독이 없어지면 Firestore/Auth 리스너와 로딩 타이머를 해제한다. 이전 구독의 콜백은 세대 번호로 무시한다.
- 로그인 UID가 바뀌거나 로그아웃되면 기존 구독을 해제하고 메모리 목록을 비운다. 다른 계정의 요청으로 복원하지 않는다.
- 최초 서버 응답 전 로딩, 빈 목록, 권한/통신/형식 오류와 재시도를 기존 `StateView`로 표시한다. 서버 응답 없이 캐시만 도착하면 10초 후 연결 오류와 재시도를 표시한다.
- 실제 프로필 저장(BT-014) 전에는 실제 요청 카드에 Mock 이름/성별/관심사/AI 이유를 붙이지 않는다. 프로필 준비 안내와 요청 목적·시간 스냅샷을 표시한다. 실제 프로필 상세·받은 요청 팝업·수락/거절은 해당 선행 연동 이후 연결한다.
- 실제 수락/거절(BT-031)은 미구현이므로 Firebase 모드에서는 버튼을 비활성화한다. Mock 시연의 수락/거절은 유지한다. 완료된 요청의 실제 매칭/채팅 상태 연결도 BT-031 이후 범위다.
- 카드·시간 요약·칩·확인창·빈 상태는 기존 컴포넌트를 재사용한다. `ConfirmDialog`에 결과 Bundle 전달만 추가해 새로 생성된 요청과 회전 후에도 같은 요청 ID로 취소한다.

## 취소 Callable

`asia-northeast3`의 `cancelMatchRequest({requestId})`.
`requestId`는 생성 API가 반환한 64자리 소문자 hex다. 추가 UID/상태/시간 입력은 거절한다.
토큰 UID가 `fromUid`인 경우만 허용하며, PENDING → CANCELED와 서버 `updatedAt`만 변경한다.
동일 요청 취소 재시도는 같은 결과를 반환한다. 수신자·제3자는 취소할 수 없고 ACCEPTED/REJECTED도 바꾸지 않는다.
원본 문서를 읽고 갱신하는 Firestore 트랜잭션으로 동시 취소 및 미래 수락 API와의 경합을 보호한다.
목적·날짜·시작/종료·겹침·생성 시각은 유지한다. UI는 서버 성공 응답 또는 리스너 반영 이후에만 목록을 갱신한다.

## 인덱스·보안 영향

`firestore.indexes.json`에 요청 컬렉션의 `(fromUid ASC, createdAt DESC)`, `(toUid ASC, createdAt DESC)`를 추가했다.
Emulator는 운영의 복합 인덱스 존재 여부를 검증하지 않는다. 실제 개발 환경 연동 때 인덱스 생성 완료를 별도로 확인해야 한다.
기존 BT-019 Rules의 참여자 읽기·클라이언트 쓰기 금지를 유지한다. 다른 데이터 경로/Rules/채팅/시간표 스키마는 변경하지 않았다.
새 API와 인덱스는 D 범위이며 A/B/SM과 통합 검토가 필요하다.

## 비용·로컬 설정

- `google-services.json`은 Git에 포함하지 않는다. 로컬 존재·Git 제외와 빌드 적용만 확인했다.
- Firebase BOM의 기존 Auth에 Functions/Firestore SDK를 추가했다. 별도 SDK 압축파일 설치는 필요 없다.
- 무료 사용량을 넘기지 않도록 검증은 `demo-bintime` 로컬 에뮬레이터와 Mock으로만 수행한다. 운영 DB/Functions/Gemini 호출·배포를 하지 않는다.
- Pixel 10 기기 테스트는 테스트 프로세스의 FirebaseApp을 제거하고 Mock임을 확인한 뒤 시작한다. 운영 인증/DB나 메일을 사용하지 않으며 제품 코드에 인증 우회나 테스트용 서버 API를 추가하지 않는다.
- 실제 연결 전에는 BT-017 후보 어댑터, 개발 환경의 함수/Rules/인덱스 적용과 검토가 필요하다. 운영 사용량 관리/알림 설정은 이번 변경 범위가 아니다.

## 검증

- 서버: `npm --prefix functions run build`, `npm --prefix functions test`.
- 로컬 Firestore: `firebase emulators:exec --project demo-bintime --only firestore "npm --prefix functions run test:emulator"`.
- Android: `gradlew.bat connectedDebugAndroidTest assembleDebug testDebugUnitTest lintDebug` (Pixel 10).
- Emulator에서 두 인증 테스트 컨텍스트의 생성/취소 리스너 갱신, 중복·멱등·시간표 변경 스냅샷 보존, 타인/미인증 읽기, 클라이언트 쓰기, 수신자/제3자 취소, 처리된 상태, 동시 취소 및 테스트 수락 트랜잭션과의 경합을 검증한다.
- 실제 계정 로그인·배포 Callable 네트워크·BT-017 적격성 판정은 검증 대상에 포함하지 않는다. 테스트 후보 어댑터는 실제 Callable에 연결하지 않는다.
