# BT-042 Gemini 교내 장소 추천 (채팅방)

E 담당. 공통 게이트웨이는 [BT-024](./BT-024.md), 약속·방 구분은 [BT-034](./BT-034.md)·[BT-035](./BT-035.md)를 따른다.

## 1. 범위

- 이번 작업: **채팅방 상단 카드의 추천 장소**만 연결한다.
- 매칭 검색 결과·프로필 노출(이슈 #42 완료 조건 일부)은 A(매칭)와 별도로 정한다. 검색 단계에는 아직 matchId 가 없고 A 화면이라 이 문서 범위 밖이다.

## 2. 호출 계약

| 항목 | 내용 |
|---|---|
| Callable | `recommendPlace({ matchId })` (asia-northeast3) |
| matchId | 개별 약속 ID. 앱은 상단 카드에 보이는 약속(`ChatAppointmentDisplay.pick`)의 ID를 보낸다. 약속 목록이 없는 이전 방은 방 키(= 첫 매칭 ID) |
| 서버가 읽는 것 | `matches/{matchId}` 의 `participantUids`·`purpose`·`dayOfWeek`·`startMinute`·`endMinute`, 두 사람의 `timetables/{uid}/courses` |
| 모델에 보내는 것 | 목적, 요일, 약속 시각, 두 사람(personA·personB)의 공강 직전·직후 **수업 건물명**(호실 제외, BT-027 `nearbyBuildings`), 후보 장소의 id·이름·건물·층·종류 |
| 보내지 않는 것 | 이름·UID·과목명·호실·시간표 원본·운영 시간·출처 |
| 응답 | `{ places: [{ placeId, name, reason }] }` 1~3곳. 앱은 이름만 " / " 로 이어 "추천 장소: …" 로 보인다 |
| 제한 | 10초(재시도 포함 전체), 하루 30회 |

## 3. 검증된 장소 목록

- 위치: `functions/src/ai/campusPlaces.ts` (`VERIFIED_CAMPUS_PLACES`, `CAMPUS_PLACES_VERSION`)
- 기준: **국민대 공식 페이지(kookmin.ac.kr)에 적힌 곳만** 넣는다. 장소마다 `source`(출처 URL)와 `verifiedAt` 을 둔다. 현재 20곳(2026-11-26 확인).
  - 교내복지시설: https://www.kookmin.ac.kr/comm/menu/user/94b421adc517815ccfa1c53d043d7d72/content/index.do
  - 생활협동조합: http://kmucoop.kookmin.ac.kr/
- 제외: 교직원식당(교직원용), 생활관식당(생활관 이용자용·출처 간 층 불일치), 도서관 열람실(만남 장소가 아니고 건물 미기재), 편의점.
- 공식 페이지에서 그룹 스터디룸·라운지는 확인되지 않았다(도서관 사이트·공간활용시스템은 스크립트·로그인 필요). 스터디 목적은 카페만 후보다.
- 장소를 바꾸면 `CAMPUS_PLACES_VERSION` 을 올린다. 저장된 추천은 버전이 다르면 다시 만든다.

### 후보 거르기

1. **목적**: 스터디·밥·카페·디저트는 그 목적에 맞는 장소만. 전체·산책·알 수 없음은 거르지 않는다.
2. **운영 시간(학기 기준)**: 약속 `[startMinute, endMinute)` 중 30분 이상(약속이 더 짧으면 약속 전체) 열려 있어야 한다.
   - 페이지에 "평일"이 있으면 그 요일만, 요일이 없으면 요일로는 거르지 않는다.
   - 운영 시간이 불확실한 장소는 `hours: null` 로 두고 거르지 않는다.
   - 운영 시간은 거르는 데만 쓰고 프롬프트·이유 문구에는 넣지 않는다. 방학 시간은 반영하지 않는다.
3. 여는 장소가 없으면 Gemini 를 부르지 않고 `AI_UNAVAILABLE`(retryable false)로 끝낸다. 호출 횟수는 쓰지 않는다.

## 4. 결과 검사

- 후보 밖·목록 밖·중복 `placeId` 는 버린다. 이름은 서버 목록 값(이름에 건물이 없으면 "이름 (건물 층)")으로 바꾼다.
- 이유 문구에 장소 자신의 건물이 아닌 두 사람의 수업 건물 이름, 또는 운영 시간·시각 표현이 있으면 기본 문구("두 분 공강 시간에 함께 가기 좋아요")로 바꾼다.
- 남는 장소가 없으면 `AI_INVALID_OUTPUT`(1회 재시도).

## 5. 저장된 추천 `placeRecommendations/{matchId}`

- `{ matchId, version, places: [{ placeId, reason }], updatedAt }`. 이름은 저장하지 않고 읽을 때 목록 값으로 채운다.
- 같은 약속은 두 사람이 같은 추천을 보고, 채팅방을 다시 열어도 Gemini·호출 횟수를 쓰지 않는다(게이트웨이 `fromCache`, `ai_call` outcome `cache`).
- 저장된 장소가 지금 후보(목적·운영 시간)에 없거나 버전이 다르면 다시 추천한다. 저장 실패는 응답을 막지 않는다(`ai_cache_save_failed` 로그).
- **서버(Admin SDK)만 읽고 쓴다. `firestore.rules` 에 이 경로의 규칙을 따로 두지 않았다.** Firestore Rules 는 일치하는 규칙이 없으면 기본 거부라 앱은 읽기·쓰기 모두 할 수 없다(`matchScores`·`aiUsage` 와 같은 방식).

## 6. 앱

- `PlaceRecommendationRepository`(경계) → `FunctionsPlaceRecommendationRepository`(Callable). 선택은 `PlaceRecommendations.get` — Firebase 모드만 호출하고, Mock 모드는 `MockChatRepository` 의 시안 문구를 그대로 쓴다.
- `ChatRoomActivity.bindMatchInfo()`: 상단 카드 약속이 처음 보이면 한 번 요청한다. 받기 전·실패하면 장소 줄을 숨긴다(BT-024 대체 흐름). 같은 약속은 화면이 열려 있는 동안 다시 요청하지 않고, 대표 약속이 바뀌면 새로 요청한다.

## 7. 배포 (E)

병합 후 `firebase deploy --only functions:recommendPlace` → `firebase functions:list`. Rules·인덱스 변경 없음.

## 8. 남은 위험

- 운영 시간은 학기 기준이다. 방학·공휴일에는 닫힌 곳이 추천될 수 있다.
- 공식 페이지 내용이 바뀌면 목록을 다시 확인해야 한다(`verifiedAt`).
- 건물 사이 거리 데이터가 없어 "같은 건물" 외에는 가까움을 판단하지 않는다.
