# BT-056 (Issue #56) 시간표·공강 경계값 회귀 테스트 (C 담당 부분, 초안)

## 범위

60·90·120·150·180분 경계값, 수업 중복·시각 경계·공강 없는 경우, 시간표 변경 뒤 기존 요청·채팅 유지. 이 문서는 C 담당(앱 시간표·공강) 부분만 다룬다.

## 이미 있는 테스트 (중복 추가하지 않음)

- BT-016·BT-036: `FreeTimeCalculatorTest`(59/60/61분, 필터 60~180의 최솟값−1·최솟값·최솟값+1, 맞닿음, 0·1440분, 요일 경계), `SlotGridTest`, `FreeCellsTest`, `FreeSlotValidatorTest`(40개 상한), `CourseValidatorTest`(겹침·맞닿음·1분 겹침·0·1440분), `MockAsyncTimetableRepositoryTest`, `TimetableDraftTest`. 표는 `docs/BT-016.md` "BT-036 경계값·재선택 검증".
- BT-047(브랜치 `feature/timetable-BT-047-preserve-snapshots`, 아직 develop 미병합): 수업 삭제 뒤 빈 칸 자동 선택 안 함, 여러 시간대·null 수업 정리, 교체 뒤 revision. `docs/BT-047.md`.
- 서버 스냅샷 보존: `functions/emulator-tests/requests.test.ts`, `request-candidates.test.ts`, `chat-link.test.ts`(BT-047 문서 "기존 보존 테스트").

## 이번에 추가한 앱 단위 테스트

`TimetableBoundaryTest`(data/repository):

- 빈 선택 저장 → availability 빈 목록, revision 유지.
- 30분 칸만 선택 → 선택 원본은 남고 매칭 대상 없음.
- 하루 전체(0~1440) 수업으로 교체 → 그날 칸 모두 정리, 다른 요일 유지, 0분·1440분 끝 칸 선택 거부.
- 10:15 시작 수업 → 10:00 칸 거부, 09:00~10:00과 11:30~12:30은 저장.
- 저장된 availability 기준으로 필터 60·90·120·150·180분 각각 정확히 같은 길이는 통과, 30분 짧으면 제외.

`TimetableDraftBoundaryTest`(timetable):

- 선택 없음 → 1시간 공강 없음, 다음 공강 없음.
- 맞닿은 수업·수업 하나뿐인 날 → 미리 선택 없음(수업 전·후는 고르지 않음).
- 하루 전체 수업 → 그날 칸 선택 불가.
- 수업 사이 정확히 1시간 → 미리 선택되고 다음 공강 카드가 그 시간.
- 수업 입력 겹침(포함·1분 겹침)은 감지, 앞뒤 맞닿음은 허용.

## 시간표 변경 뒤 기존 요청·채팅 유지

- 앱 쪽 근거는 BT-047(시간표 저장 경로가 matchRequests·matches·채팅을 읽거나 쓰지 않음)이다. 앱 단위 테스트로 Firestore 쓰기 대상을 검사할 수 없어 새로 추가하지 않았다.
- 서버 에뮬레이터 테스트 d·e·f 초안은 공용 폴더(`functions/emulator-tests`)라 A의 허락 뒤 추가한다. 초안은 PR 본문 또는 별도 전달 자료로 공유한다.

## 검증

- `./gradlew testDebugUnitTest assembleDebug lintDebug`: 통과(`TimetableBoundaryTest` 5개, `TimetableDraftBoundaryTest` 6개 추가).
- `cd functions && npm run build && npm test`: 통과(16개 파일, 260개). functions 는 바꾸지 않았다.
- 에뮬레이터 테스트는 실행하지 않았다.
