# BT-008 / Issue #8 — 알림·요청 수신 목업

## 범위와 재사용

- 담당 D(notification), 선행 #2·#7 CLOSED 확인. Java/XML 및 기존 테마·칩·시간 요약·기본 프로필·StateView·마우스 스크롤 컴포넌트 재사용.
- Figma: 알림 목록 `41:24797`, 요청 팝업 `41:10578`, 설정 `120:2200`. 성공 화면은 BT-007의 MatchAcceptedActivity 재사용.
- 홈 알림 버튼 → 알림 목록, 마이 자리 표시자 → 알림 설정. 메시지·매칭 성사·요청·후기 4종 Mock 알림 제공.
- 요청 저장소 소유자를 MainActivity로 옮겨 요청 탭·팝업·알림이 같은 상태를 참조한다. 수락·거절 및 충돌 정리는 기존 MockRequestRepository에 위임하고, 상태 스냅샷을 중복 저장하지 않는다.
- 최초 홈 진입 시 대기 요청을 세션당 한 번 자동 표시한다. 닫기·뒤로가기는 거절하지 않는다. 이미 처리된 요청은 재수락·재거절하지 않으며 알림 기록은 유지한다.
- 알림 종류별 6개 스위치와 팝업 표시 스위치는 기기 내 SharedPreferences에 저장한다. FCM 구독이나 OS 권한을 변경하지 않는다. 종류별 스위치는 설정 목업이며 고정 시연 알림 목록을 삭제·필터링하지 않는다.
- 오늘 팝업 끄기는 Asia/Seoul 날짜로 저장하며 다음 날짜부터 해제된다. 자동 표시만 억제하고, 목록에서 요청을 수동으로 여는 동작은 허용한다.
- 날짜 제목을 길게 누르면 Mock 알림 유무를 전환해 빈 상태를 시연할 수 있다. 설정 스위치와 달리 알림 빈 상태·요청 변경은 새 세션에서 초기화한다(화면 재생성 시에는 복원).

## 검증

Pixel 10 화면 증거: [요청 수신 팝업·선택된 체크박스](./screenshots/BT-008/request-popup.png), [알림 목록 4종](./screenshots/BT-008/notification-list.png).

- `gradlew.bat assembleDebug testDebugUnitTest lintDebug` 통과. 테스트 총 14개(기존 10개 + 알림/팝업 정책 4개), 실패·오류 0.
- 신규 테스트: 시연 알림 4종과 유효한 요청 참조, 알림 수락 후 동일 저장소 반영·중복 거부, 거절 후 재처리 거부·기록 보존, 날짜 변경 시 억제 만료·스위치 OFF 우선.
- Pixel 10: 팝업 자동 표시·닫기·목록에서 재열기, 알림 4종, 알림에서 수락 → 기존 성공 화면 → 수락 완료 표시, 빈 상태와 가로·세로 회전 복원 확인.
- 설정 화면 재진입 시 메시지 알림 스위치 변경 유지 확인 후 초기값으로 복원했다. 팝업의 오늘 끄기를 체크한 뒤 앱 재실행 시 자동 팝업이 나타나지 않는 것을 확인했다.
- 목록/팝업/설정 화면을 캡처해 Figma와 비교했다. 사진·프로필·날짜는 실제 Mock 데이터 기준으로 표시한다.
- 오늘 팝업 끄기는 MaterialCheckBox로 표시한다. 미선택은 흰색 테두리, 선택은 action_primary 빨간 배경과 흰 체크로 구분한다. Pixel 10에서 선택 표시를 확인하고 `assembleDebug lintDebug`를 통과했다.
- 거절 버튼의 Pixel 10 조작 결과는 확정하지 못했으며, 거절 상태 변경·재처리 차단은 단위 테스트로 검증했다. 메시지/후기 항목의 실제 서버 화면 이동도 후속 통합 검증 대상이다.

## 영향·남은 작업

- A/SM 검토: MainActivity의 공용 Mock 저장소와 알림 화면 내비게이션, 공개된 MatchSummaryBinder.bind. B 검토: 마이 자리 표시자의 알림 설정 진입점. 기존 팀별 구조는 유지했다.
- 신규 서버 컬렉션·Rules·API·FCM·비밀값 변경 없음. 알림 설정 Activity는 exported=false. 실시간 서버 수신·2계정·네트워크/권한 오류·FCM 전송 검증은 미실행이다.
- 실제 채팅방·후기 화면은 후속 담당 기능 연동 필요. 현재 메시지는 채팅 탭으로 이동하며 후기 항목은 준비 안내만 표시한다.
- 시연 데이터의 생성 시각은 고정이며 실제 푸시 도착 시간이나 읽음 상태를 의미하지 않는다.
- README에 작업 참고사항을 추가하지 않는다. 팀원 리뷰·통합 확인 전 이슈 완료로 간주하지 않는다.
