# BT-007 / Issue #7 — 요청 탭 목업

담당 영역 D (`request`). 선행 BT-002 / #2는 작업 시작 시 CLOSED 상태를 확인했다.

## 구현

- Figma 노드: 보낸 요청 `41:24471`, 받은 요청 `41:24390`, 완료된 매칭 `101:2119`, 매칭 수락 후 확인 `41:10882`.
- 기존 4개 상단 탭을 유지하고 요청 탭의 자리 표시자를 카드 목록으로 교체했다.
- 추가 요청: 보낸 요청에도 성별을 표시한다(`41:24471`). 프로필 상세 더보기의 `신고하기`(`116:3776`), 홈 정렬의 `AI 추천순` / `빠른 시간순`(`274:1977`)은 공통 `ActionMenu` 팝업으로 표시한다. 신고 접수·정렬 적용은 이번 요청 범위에 포함하지 않으며, 해당 항목을 누르면 준비 중 안내만 표시한다. 메뉴를 닫아도 현재 정렬은 바뀌지 않는다.
- 공강 상태 카드, 테마, 버튼, 기본 프로필 이미지, ChipViews, StateView, ConfirmDialog를 재사용했다. 기존 시간 요약 XML은 `view_time_overlap.xml`로 분리하여 매칭 찾기·프로필 상세·요청 카드·수락 후 확인 화면이 공유한다.
- 수락 후 작은 성공 팝업 대신 `MatchAcceptedActivity` 전체 화면을 표시한다. Figma의 체크 아이콘·상대 이름·공강 스냅샷·관심 태그·채팅하기·홈으로 가기를 구성했다. 채팅하기는 기존 채팅 탭(현재 자리 표시자), 홈으로 가기는 매칭 찾기로 이동한다. 뒤로가기는 요청 탭으로 돌아간다. 외부 앱에서 확인 화면을 직접 열 수 없도록 exported=false로 등록했다.
- 취소·거절 시 해당 대기 목록에서 제거하고, 수락 시 완료된 매칭 목록에 ACTIVE로 표시한다. ENDED 예시는 초기 Mock 데이터로 제공한다. 거절·취소 기록은 Mock 저장소에 남긴다.
- 날짜·시간 스냅샷은 final 필드로 보존한다. 같은 날짜의 시간 충돌만 비교하며 대기 요청 정리도 Mock 저장소 안에서만 수행한다.
- 선택 탭과 상태를 savedInstanceState에 저장한다. 다이얼로그 결과는 요청 ID·동작별 키와 화면 생명주기로 처리한다.

- `gradlew.bat assembleDebug testDebugUnitTest lintDebug`: 통과.
- 기존 매칭 저장소 테스트 6개와 신규 요청 저장소 테스트 4개 통과(실패·오류 0).
- 신규 테스트: 수락 후 목록 이동·충돌 요청 정리·스냅샷 보존, 거절, 잘못된 동작·중복 처리 거부, 직렬화 복원.
- Pixel 10 에뮬레이터: 앱 설치·실행, 세 요청 탭 이동, 보낸 요청 취소 후 개수 0·빈 화면, 받은 요청 수락 확인·성공 안내, 완료 목록 2건과 ACTIVE/ENDED 구분, 가로·세로 회전 후 탭·수락 상태 유지 확인.
- 보낸 요청·완료된 매칭 화면 캡처를 Figma와 비교했다. 사진은 동적 프로필의 기존 기본 이미지, 태그는 기존 Mock 프로필 데이터를 사용한다. 목록 개수는 실제 Mock 항목 수이며 Figma 예시 숫자를 하드코딩하지 않는다.
- 수락 후 확인 전체 화면을 Pixel 10에서 Figma와 비교하고, 회전 후 상대·시간 표시 유지, 홈으로 가기 → 매칭 찾기, 채팅하기 → 채팅 탭 이동을 확인했다. README에는 작업 참고사항을 추가하지 않는다.
- 추가 메뉴는 Pixel 10에서 실제 버튼을 눌러 열고 Figma와 시각 비교했다. 빌드·기존 단위 테스트 10개·린트 검사를 통과했다. 프로필 메뉴는 화면 중단 시 닫고 정렬 메뉴는 뷰 해제 시 닫는다.
- 추가 UI 수정: 요청 취소 팝업을 `닫기` / `요청취소`로 구분하고, 다른 확인창은 기존 취소 문구를 유지한다. 받은 요청의 프로필 보기 화살표는 글자와 같은 회색(`text_tertiary`), 글자와 간격은 8dp로 조정했다.
- 상단 탭과 스크롤 영역 사이 12dp 간격을 고정해 내용이 올라와도 유지한다. 마우스 휠은 `MouseWheelScrollView`에서 이벤트당 최대 48dp로 제한하며 터치·키보드·기타 입력은 기존 처리를 사용한다.
- Pixel 10 입력 검증: 수정 전 큰 마우스 휠 값(`VSCROLL=-120`)에 마지막 카드까지 이동하던 현상을 재현했다. 수정 후 같은 입력은 첫 카드 위치가 1126px → 1000px로 126px(48dp) 이동하고 탭 아래 32px(12dp) 간격을 유지했다. 역방향 입력, 취소 팝업 문구, 회색 프로필 화살표 및 활성 채팅하기 버튼도 확인했다.
- 거절 버튼의 에뮬레이터 조작, 실제 서버·2계정·네트워크 실패 검증은 미실행. 거절 상태 변경은 단위 테스트로 검증했다.
- 기존 공강 카드의 고정 `오늘(월)` 문구와 매칭 찾기 목업 정보는 이번 요청 화면 작업에서 유지했다.

## 후속 연동 및 검토

- 현재 화면은 BT-007 목업이다. 기존 매칭 찾기의 신청 데이터와 이번 요청 목록은 독립된 Mock이며 후속 요청 API 연동 시 통합해야 한다.
- Firebase 인증·서버 트랜잭션·보안 Rules·채팅방 생성·후기 저장은 구현하지 않았다. 서버 권한·스키마 변경은 없다.
- ACTIVE의 `채팅하기` 버튼은 기존 채팅 탭으로 이동한다(실제 대화방 연동은 후속 작업). ENDED의 후기 버튼은 후속 기능 안내만 표시한다.
- A/SM 검토 대상: MatchingFragment 탭 연결부 및 공통 시간 요약 추출에 따른 매칭 찾기·프로필 상세 영향. 기존 매칭 찾기 테스트·빌드는 통과했으며 프로필 상세 화면의 추가 시각 회귀 확인을 권장한다.
- 추가 메뉴 변경 검토 대상: A/SM의 매칭 정렬 진입점, B의 프로필 신고 진입점. 서버 API·Rules·Enum 변경 없이 메뉴 표시만 추가했으며 향후 실제 기능 연결이 필요하다.
- 팀원 리뷰와 통합 검증 전까지 이슈 완료로 간주하지 않는다.
