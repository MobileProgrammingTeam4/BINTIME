# BT-016 (Issue #16)

## 목적

수업 사이 공강 목록을 산출하고, 30분 칸 선택을 공강 구간으로 바꾸고, 두 공강의 교집합을 분 단위로 계산하고, 최소 겹침(60·90·120·150·180분)을 판정하는 **순수 계산 로직**을 추가한다. 화면(`timetable/`)·Firestore·서버 함수와는 아직 연결하지 않는다.

- 코드: `app/src/main/java/com/team4/bintime/data/availability/` (`SlotGrid`, `FreeTimeCalculator`)
- 테스트: `app/src/test/java/com/team4/bintime/data/availability/`
- `util/TimeUtils`, `data/model/*`, `timetable/` 은 수정하지 않았다.

## 09:00 기준 행 vs 자정 기준 칸

| 구분 | 기준 | 범위 | 사용처 |
|---|---|---|---|
| 자정 기준 칸 (**팀 결정**) | `칸 = minute / 30` | 0 ~ 47 (하루 48칸) | `SlotGrid`, `timetable/TimetableDraft` (`getStartSlotIndex(0)`, `long` 비트마스크) |
| 09:00 기준 행 (기존) | `행 = (minute - 540) / 30` | 0 ~ 17 (09:00~18:00) | `TimeUtils.minutesToSlotIndex` 등, `TimeSlot.getStartSlotIndex/getEndSlotIndex` |

- 변환식: **`칸 = 행 + 18`** (`BASE_HOUR * 2`). **09:00~18:00 범위에서만 성립**한다.
- 기존 09:00 기준 메서드는 09:00 이전을 0, 18:00 이후를 17로 잘라내므로 범위 밖 정보가 사라진다. 따라서 계약으로 쓰지 않는다.
- 계약(저장·전달·비교)은 언제나 **분 단위**이고, 칸은 공강 선택 UI 단위다. 칸 단위(30분)와 최소 겹침 필터(60분~)는 별개다.
- 변환식은 `SlotGridTest.legacyNineOClockRow_equalsSlotMinus18`에서 확인한다.

## API 요약

### `SlotGrid` (자정 기준 30분 칸)

| 메서드 | 설명 |
|---|---|
| `SLOT_MINUTES=30`, `MINUTES_PER_DAY=1440`, `SLOTS_PER_DAY=48` | 상수 |
| `int slotOf(int minute)` | 0..1439 → 0..47, 범위 밖은 `IllegalArgumentException` |
| `int startSlotOf(int startMinute)` | 시작 칸(내림) |
| `int endSlotOf(int endMinute)` | 종료 칸(올림, exclusive). 1440 → 48 |
| `int slotStartMinute(int slot)` / `slotEndMinute(int slot)` | 칸 → 분 |
| `List<TimeSlot> cellsToSlots(int dayOfWeek, long cellMask)` | 선택 칸(비트 i = 칸 i)을 연속 구간으로 합침. 자정을 넘겨 잇지 않음 |

### `FreeTimeCalculator` (공강·교집합·최소 겹침)

| 메서드 | 설명 |
|---|---|
| `List<TimeSlot> normalize(List<TimeSlot>)` | 유효하지 않은 구간 제거, 같은 요일의 겹침·맞닿음 병합, (요일, 시작) 정렬 |
| `List<TimeSlot> gapsBetweenCourses(List<TimeSlot> courseSlots)` | 수업 사이 공강(분 단위). 첫 수업 전·마지막 수업 후 제외, 수업 0~1개인 요일은 없음 |
| `long selectableCells(List<TimeSlot> courseSlots, int dayOfWeek)` | 수업과 1분도 겹치지 않는 칸만 선택 가능 (예: 10:15 종료 수업 → 10:00 칸 불가, 10:30 칸부터 가능) |
| `List<TimeSlot> intersect(List<TimeSlot>, List<TimeSlot>)` | 같은 요일끼리의 교집합(분 단위) |
| `List<TimeSlot> matchableOverlaps(mine, theirs, int minOverlapMinutes)` | 교집합 중 `>= minOverlapMinutes` |
| `boolean meetsMinOverlap(int overlapMinutes, int minOverlapMinutes)` | `overlap >= min` |
| `List<TimeSlot> matchableFreeSlots(List<TimeSlot> freeSlots)` | 병합 후 60분 이상인 매칭 대상 공강 |

공통 규칙:

- 구간은 반열린 `[start, end)`. 끝=시작으로 맞닿으면 겹침 0분이다.
- `minOverlapMinutes`는 `TimeUtils.isValidMinOverlap` 기준 {60, 90, 120, 150, 180}만 허용하며, 그 밖의 값(0, 30 등)은 `IllegalArgumentException`.
- 비교는 **같은 요일(`dayOfWeek`)끼리만** 한다. 실제 날짜(`meetingDate`)와 "지금 겹치는 공강 우선, 없으면 가까운 미래"는 매칭 검색(BT-017, `searchMatches`) 범위다.
- 반환 `TimeSlot`은 항상 새 인스턴스이며 입력 목록을 변경하지 않는다.
- 재사용: `TimeUtils.overlapMinutes`, `isValidMinOverlap`, `DEFAULT_MIN_OVERLAP`, 모델 `TimeSlot`.
- `TimeSlot`이 `Parcelable`이라 `android.os`를 참조하지만, 새 클래스 자체는 `android.*`를 import하지 않으며 JVM 단위 테스트로 검증한다.

## 수용 기준

| 기준 | 상태 |
|---|---|
| ① 30분 공강 선택은 가능하되 60분 미만 매칭은 제외 | **이번 PR에서 충족** — `cellsToSlots`, `matchableFreeSlots`, `matchableOverlaps` |
| ② 시작·종료 경계값 테스트 통과 | **이번 PR에서 충족** — 59/60분, 시작=끝, 0/1440 하루 경계, 수업 없는 날, 0~180분 × 필터 경계표 |
| ③ 매칭 대상 공강이 Firestore에 저장 | **범위 밖** — BT-013·BT-015 이후 연결 |

## 범위 밖 후속 작업

- ③ Firestore `availability/{uid}` 저장 (BT-013·BT-015 이후, `sourceRevision` 포함).
- `timetable/TimetableDraft`의 공강 선택·`suggestGaps`·`nextFreeWindow`를 이 계산기로 연결 (시간표 화면 이슈).
- `TimeUtils`/`TimeSlot`의 09:00 기준 칸 메서드를 `SlotGrid`에 위임하거나 `@Deprecated` 처리 (BT-012 담당자와 합의 후 별도 PR).
- 날짜 기반 교집합·현재/가까운 미래 선택·양측 매칭 스위치·목적·차단 조건 (BT-017 / A 담당 `searchMatches`).
