추가 확정: 시작 시각 전에 수동 종료한 매칭은 후기 대상에서 제외한다. 나중에 원래 시작 시각이 지나도 자격을 부여하지 않으며 종료 시각과 원래 시작 시각의 서버 판정을 보존해 BT-044에 전달한다.

여러 약속의 나가기 처리 권장안: 연결된 매칭 중 미종료 약속이 하나라도 있으면 나가기를 막고 해당 약속과 건수를 안내한다. 모든 매칭 종료 후 나가기를 허용한다. 새 매칭 성사/나가기 경합은 서버에서 순서를 보호하여 성사가 먼저면 나가기를 거절하고, 나가기가 먼저면 새 매칭은 새 방으로 연결한다. 이는 ACTIVE 나가기 금지를 여러 연결에 적용한 제안이며 실제 BT-043 연동 시 사용자 확인과 E의 계약 검증을 거친다.

기존 방의 chatReady=false는 **전송/재사용 불가**를 뜻하며 남은 사람의 과거 메시지 읽기까지 막지 않는다. 새 매칭의 새 방은 별도로 true가 될 수 있다. 기존 스키마에서 chatReady는 매칭 모델의 값이므로, 방 수준 정책과 매칭별 준비 상태를 어떻게 저장할지 명시적으로 구분한다.

## 구현 계획과 D/E 분담

1. **D/E 계약을 먼저 맞춘다.** 새 매칭과 기존 방의 연결, 방 생성 요청/결과, 참여자 UID, chatReady의 원본, 생성 실패·재시도, 나가기/이전 대화의 읽기/쓰기 권한을 정의한다. 원래 이슈의 D–E 초기 계약 합의 요구를 먼저 충족한다.
2. **확정 생성은 BT-031 공통 경로를 재사용한다.** 수락·매칭 생성·충돌 보호는 같은 Firestore 트랜잭션에 두고, 요청당 한 번만 생성한다. BT-033은 스냅샷과 조회·완료 탭·채팅 연계를 완성하며 별도 중복 생성 경로를 만들지 않는다.
3. **채팅 생성/연결 요청을 복구 가능한 형태로 남긴다.** Firestore와 RTDB를 단일 원자적 트랜잭션으로 가정하지 않는다. 프로세스 종료 후에도 미완료 작업을 재시도할 수 있게 하고, RTDB 성공 후 Firestore 준비 표시가 실패한 경우 기존 방을 확인해 연결을 완성한다. 트랜잭션 재실행 중 RTDB 생성 같은 외부 부수 효과를 직접 실행하지 않는다.
4. **E의 BT-034와 실제 방 연결을 구현한다.** D는 확정 매칭·준비 상태와 생성 요청을 제공한다. E는 방·양측 사용자 목록·권한·매칭 정보 소스를 연결하는 책임을 계약에 명시한다. 함수·경로의 이중 소유와 서로 다른 방 중복 생성을 피한다. 정확한 구현 파일 분담은 계약 PR에 기록한다.
5. **동일 상대의 이전 방 상태로 분기한다.** 둘 다 남으면 기존 방, 한 명 또는 둘 다 나갔으면 보관한 이전 방과 구분해 새 매칭용 방을 준비한다. 둘 다 나간 이전 방은 사용자에게 숨기고 서버에만 보관한다. 기존 방과 새 방에 같은 상대가 있어도 기록·안읽음·최근 메시지를 잘못 합치지 않는다.
6. **이전 대화 접근을 실제로 제한한다.** 현재 RTDB Rules는 멤버에게 전체 메시지 읽기와 새 쓰기를 허용하므로 화면에서만 메시지/입력창을 숨기지 않는다. 나간 사람은 이전 기록을 읽지 못하고 남은 사람은 읽기만 가능하도록 권한·서버 전송을 검증한다. 이미 내려받은 기기 기록을 원격으로 회수할 수 있다고 보장하지는 않는다.
7. **Android 흐름을 연결한다.** 기존 `MatchAcceptedActivity`, 완료된 매칭 카드, 채팅 목록·방·상태 컴포넌트와 공개 프로필·사진 로더를 재사용한다. 서버 준비 전에는 채팅 준비 중/실패/재시도를 구분하고, 준비 완료 후 같은 실제 방으로 이동한다. 이전 대화는 승인된 배지·문구·읽기 전용 표현을 적용한다. 기존 Figma와 충돌하는 신규 표현은 최신 사용자 결정을 문서화해 반영한다.

BT-043의 나가기 기능 전체를 구현 완료한 것으로 보고하지 않는다. 이번에는 새 매칭에서 사용할 방 선택·복구·권한 계약과 필요한 E 연동을 구현하고, 향후 실제 나가기 호출과 그 상태 생성은 BT-043과 연결한다. 나간 상태를 주입한 로컬 테스트와 실제 나가기 E2E는 구분한다.

- 동일 요청 수락 재시도·생성 이벤트 중복·중간 프로세스 종료에서 요청당 매칭 한 건과 동일 방 연결을 확인한다.

- 기존 방의 둘 다 잔류/한 명 이탈/둘 다 이탈 조합과 이전 대화 배지·새 방 분리를 검증한다. 남은 사람 읽기 허용·쓰기 거부, 나간 사람 읽기/쓰기 거부, 새 방 양측 전송 허용을 Rules 테스트로 입증한다.

- ENDED 양측 잔류 대화는 전송 가능, 이전 대화는 읽기 전용, ACTIVE 나가기 거부를 각각 구분한다. 실제 나가기 API가 아직 없으면 해당 E2E는 미실행으로 표시한다.
- 계획 명령: `npm --prefix functions run build`, `npm --prefix functions test`, 로컬 Firestore/RTDB Emulator의 `npm --prefix functions run test:emulator`, `gradlew.bat assembleDebug testDebugUnitTest lintDebug`, Pixel 10 UI 테스트·스크린샷.
- 로컬 `demo-bintime`에서 실행하고 프로젝트 ID·호스트·Rules를 확인한다. 운영 Firebase/Gemini 호출·데이터 삭제·배포·비용 설정 변경은 이번 계획에 포함하지 않는다.

## 이번 계획 준비의 실행 상태
