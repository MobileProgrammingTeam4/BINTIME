## 1. 정책

| 항목 | 기준 |
|---|---|
| 매칭 종료 | BT-038 이 `matches` 를 ENDED 로 바꾼다. 메시지·멤버·전송 권한은 바뀌지 않는다. **둘 다 남은 방은 종료 후에도 송수신** |

| 둘째 이탈 | 남은 사람도 멤버 제거·`hidden`. 메시지는 서버에 보관(최종 삭제는 신고 담당·SM 후속 합의) |
| 다음 약속 | 같은 두 사람의 다음 연결은 새 방(BT-033 기존 동작). 이전 방은 남은 사람에게 이전 대화로 남는다 |
| 메시지·안읽음 | 나가기로 지우거나 바꾸지 않는다 |

## 2. 서버 `leaveChatRoom({chatRoomId})`

- 파일: `functions/src/chat/leave.ts`(`ChatLeaveService`), `functions/src/chat/leaveCallable.ts`, `functions/src/index.ts` export.
- 리전 `asia-northeast3`, 로그인·학교 이메일 확인(기존 `emailPolicy`). 입력은 64자리 hex 방 키 하나(`.strict()`, UID·상태 입력 거부).

### 처리 순서

1. **Firestore 트랜잭션**: `chatRoomLinks/{roomId}` 의 `pairId`·`participantUids`, `chatPairs/{pairId}`, `matches where chatRoomId == roomId` 를 읽는다.
   - 방 링크 없음·pair 참여자 아님 → `permission-denied`
   - 이미 나감(pair 참여자지만 `chatRoomLinks.participantUids` 에 없음) → 성공(멱등)
   - ACTIVE 약속 있음 → `failed-precondition {reason: ACTIVE_MATCH}`
   - `pendingMatchId` 있음 또는 `roomStateLeaseUntil` 유효 → `failed-precondition {reason: RETRY_LATER, retryAfterMillis}`
   - 통과: `stateRevision +1`, `roomStateOwner = <uuid>`, `roomStateLeaseUntil = now + 120초`
2. **RTDB update 한 번**: 위 1장 첫/둘째 이탈 표의 경로. 제3자 멤버가 있는 잘못된 방은 `INVALID_ROOM`. 없는 목록 항목은 부분 필드로 다시 만들지 않는다.
3. **Firestore 트랜잭션**: `chatRoomLinks` 의 `participantUids` 에서 나를 빼고 `archived:true, chatReady:false`. 내가 잡은 lease 만 푼다.

RTDB 반영이 실패하면 lease 를 풀고 `RETRY_LATER`. RTDB 반영 뒤 3단계가 실패하면 다시 불렀을 때 RTDB 를 같은 값으로 덮고 3단계를 마친다. lease 를 못 풀어도 120초 뒤 만료된다.

### BT-038 잠금 계약 (#121 코드로 확인, 2026-11-24)

| 필드 (`chatPairs/{pairId}`) | #121 코드의 값 | 나가기 |
|---|---|---|
| `pendingMatchId` | 연결 중 matchId, 끝나면 `null` (`link.ts`) | 값이 있으면 거절 |
| `roomStateOwner` | `randomUUID()`, 해제 시 `null` (`roomState.ts`) | 같은 형식으로 잡고, 내 값일 때만 해제 |
| `roomStateLeaseUntil` | `Timestamp`, now + 120,000ms, 해제 시 `null` | 유효하면 거절(남은 ms 전달), 같은 길이로 잡음 |
| `stateRevision` | `FieldValue.increment(1)` (`endMatch.ts`) | 같은 트랜잭션에서 +1 |

- `matches` 조회는 `chatRoomId` 단일 조건이라 복합 인덱스가 필요 없다(#121 의 `matches(chatRoomId,status)` 인덱스에 의존하지 않음).
- `chatPairKey` 는 첫 이탈 뒤 참여자 목록으로 다시 계산할 수 없으므로 `chatRoomLinks.pairId` 를 쓴다.
- **#121 병합 전 위험**: develop 의 `link.ts` 는 아직 `roomStateLeaseUntil` 을 보지 않는다(#121 에서 추가). 병합 전에는 나가기 도중 같은 두 사람의 새 연결이 끼어드는 경합이 열려 있다.

## 3. 앱 (`chat/`)

| 파일 | 내용 |
|---|---|
| `ChatRepository` | `leaveRoom(roomKey, LeaveCallback)`, `LeaveCallback.onError(ChatLeaveFailure)` |
| `ChatLeaveFailure` | `ACTIVE_MATCH` / `RETRY_LATER`(네트워크·일시 오류 포함) / `PERMISSION` / `SIGNED_OUT` / `GENERIC` |
| `FirebaseChatRepository` | `leaveChatRoom` Callable. 호출 중 로그인 계정이 바뀌면 `SIGNED_OUT` |
| `MockChatRepository` | 서버와 같이 연결된 약속 중 ACTIVE 가 있으면 `ACTIVE_MATCH`, 데모 오류 상태는 `RETRY_LATER` |
| `ChatRoomActivity` | 옵션 ⋯ → '채팅방 나가기' |

화면 동작:

- 방 상태 또는 연결된 약속 중 ACTIVE 가 있으면 확인 창 대신 BT-010 안내 다이얼로그 '채팅방을 나갈 수 없어요 / 현재 진행중인 매칭을 먼저 종료해주세요'.
  ACTIVE 약속이 모두 종료 시각을 지났으면(자동 종료 반영 전) '매칭 종료를 처리하고 있어요. 잠시 후 다시 시도해주세요'.
- 서버가 `ACTIVE_MATCH` 로 거절해도 같은 안내. `RETRY_LATER`·권한·로그인 만료는 각각 안내, 그 밖은 기존 실패 문구.
- 성공하면 '채팅방을 나갔어요' 후 화면을 닫는다. 목록은 `hidden` 항목을 빼므로(`ChatRtdbMapper`) 바로 사라진다.
