# BT-028 / Issue #28 — AI 추천순 정렬·점수 캐시

담당 A. 점수 산정·입력 계약은 [`BT-027.md`](./BT-027.md), 검색 계약은 [`BT-017.md`](./BT-017.md)를 따른다.
구현: `functions/src/matching/score.ts` (`addScores`, `rankByScore`, `inputHash`, `FirestoreScoreData`).

## 흐름

```text
searchMatches (필수 조건, 겹침 긴 순)
  → 상위 5명마다 AI 입력 만들기 → inputHash
  → matchScores 캐시가 같은 해시·만료 전·점수 0~100 이면 그 값 사용 (Gemini 호출 없음)
  → 아니면 evaluateMatch 호출 → live 결과만 캐시에 저장
  → 15초 마감까지 안 끝난 후보는 점수 없이(BT-027)
  → 상위 5명 안에서 점수 높은 순 정렬 → 6번째부터는 그대로 뒤에
```

## 정렬 (AI 추천순)

| 순서 | 기준 |
|---|---|
| 1 | 점수 있는 후보: 점수 높은 순 |
| 2 | 동점: 기존 순서(겹침 긴 순 → 이른 시작 순) |
| 3 | 상위 5명 중 점수 없는 후보(AI 실패·프로필 부족): 기존 순서 |
| 4 | 6번째 이후 후보: 점수 없이 기존 순서 |

- 점수 0은 점수 있음이다(점수 없음보다 앞). 앱은 서버 순서를 그대로 보여준다(`AI 추천순` 메뉴 기본값).
- AI는 필수 조건 통과 후보에만 쓰고, 점수로 부적격 후보를 되살리지 않는다(AGENTS §6).

## 캐시 `matchScores/{searcherUid}_{candidateUid}`

| 필드 | 값 |
|---|---|
| `searcherUid`, `candidateUid` | 검색자·후보 UID |
| `inputHash` | AI 입력 JSON + 프롬프트(`SYSTEM_INSTRUCTION`) + 모델(`GEMINI_MODEL`) + `SCORE_CACHE_VERSION`의 SHA-256 |
| `score`, `reasons`, `suggestedActivity` | `evaluateMatch` 결과 |
| `expiresAt` | 저장 시각 + 24시간 (Timestamp) |
| `updatedAt` | 서버 시각 |

- **서버 전용.** `firestore.rules`에 규칙이 없어 앱은 읽기·쓰기 모두 거부된다(`aiUsage`와 같은 방식). Rules 변경·배포는 필요 없다.
- 캐시를 못 읽거나 못 쓰면 무시하고 평가·표시를 계속한다. 검색은 멈추지 않는다.
- Mock 모드 점수는 저장하지 않는다(live로 바꾼 뒤 가짜 점수가 남지 않게).

## 재평가 기준

해시는 AI 입력 전체로 만든다. 아래 중 하나라도 바뀌면 다시 평가한다.

| 바뀌는 것 | 입력 필드 |
|---|---|
| 필터 목적 | `purposes` |
| 공강·겹침 (30분 단위) | `overlapMinutes` |
| 프로필(학과·학년·태그·자기소개) | `searcher`/`candidate` |
| 시간표(공강 앞뒤 수업 건물, 함께 듣는 수업) | `nearbyBuildings`, `commonCourses` |
| 프롬프트 | `SYSTEM_INSTRUCTION` (자동) |
| Gemini 모델 | `GEMINI_MODEL` (자동) |
| 출력 검사 등 그 밖의 규칙 | `SCORE_CACHE_VERSION` (코드에서 올림, 현재 3: #102 건물명 검사, BT-049 근거 검사) |
| 시간 경과 | 24시간 만료 |

## 효과

- 같은 공강에서 새로고침하면 점수·이유가 바뀌지 않는다(BT-027 실기기에서 발견된 문제).
- 반복 검색 시 Gemini 호출과 `aiUsage` 한도 사용이 줄어든다(같은 입력이면 0회).

## 검증

- `functions/test/score.test.ts` "BT-028 점수 캐시·추천순": 반복 검색 시 호출 1회, 겹침 30분 단위·프로필 변경·24시간 만료 시 재평가, Mock 미저장, 저장 실패에도 점수 표시, 범위 밖 캐시 무시, 정렬·동점·점수 없음 순서.

## 참고 (#117 E 리뷰)

- 캐시가 맞으면 `runAiTask`를 거치지 않아 `aiUsage` 차감과 `ai_call` 로그가 없다. 로그 건수는 검색 수와 다르다.
- 실패는 캐시하지 않아 같은 후보가 계속 실패하면 검색마다 1회씩 차감된다. 필요하면 짧은(예: 10분) 실패 캐시를 후속으로 둔다(BT-049에서도 운영 실패가 없어 보류).
- 동시에 들어온 같은 평가는 한 번만 호출·차감·저장한다(BT-049, [`BT-049.md`](./BT-049.md)).
- 진행 중인 공강은 남은 시간이 30분 단위로 바뀌어 30분마다 다시 평가된다(후보 5명이면 30분마다 최대 5회). 의도한 동작이다.

## 남은 것 (후속)

- 만료 문서 정리: Firestore TTL 정책을 `matchScores.expiresAt`에 걸 수 있다(콘솔 설정, 배포 담당). 걸지 않아도 만료 문서는 읽을 때 무시된다.
- 탈퇴 시 해당 UID가 들어간 `matchScores` 삭제는 탈퇴 처리 담당과 맞춰야 한다.
- `시간순` 정렬 메뉴는 아직 "준비 중"이다.
