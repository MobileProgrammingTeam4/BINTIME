# BT-021 / Issue #21 — 채팅 데이터 모델·채팅방/메시지 실시간 구독

채팅은 Realtime Database(RTDB)에 저장한다. 이 이슈는 **RTDB 데이터 모델·구독(읽기)·보안 규칙**까지이고, 메시지 전송과 화면 연결은 BT-022에서 한다. 경로·필드는 [BT-012](./BT-012.md) RTDB 절과 PR #77 합의를 따른다.

- RTDB 인스턴스: `bintime-mobile-default-rtdb` (**asia-southeast1**). 앱은 `google-services.json`의 `firebase_url`을 그대로 쓰고 주소를 코드에 넣지 않는다. 실제 RTDB로 테스트하기 전에 [아래 확인](#google-servicesjson-확인)을 먼저 한다.
- 보안 규칙: 저장소 루트 `database.rules.json` (`firebase.json`의 `database.rules`)
- 실제 프로젝트에는 **아직 규칙을 게시하지 않았다.** 콘솔 규칙은 읽기·쓰기 모두 `false`로 잠겨 있다. 게시는 BT-022 실기기 검증 때 승인 후 진행한다.

## 1. 데이터 구조

```text
chatRooms/{matchId}/members/{uid}:     { joinedAt }
chatRooms/{matchId}/messages/{pushId}: { senderId, content, createdAt }
userChatRooms/{uid}/{matchId}:         { otherUid, lastMessage, lastMessageAt, unreadCount, status, hidden }
```

| 항목 | 계약 |
|---|---|
| `matchId` | `matches/{matchId}` 문서 ID = `requestId`(64자리 hex). 별도 roomId 없음 |
| `messageId` | RTDB push 키. 노드 안에 저장하지 않고 snapshot key로 읽는다 |
| `senderId` | 필수. Rules에서 `=== auth.uid` |
| `content` | 문자열 **1~1000자**, 공백(스페이스·탭·줄바꿈)만 있으면 거부. **최대 1000자는 이 이슈에서 확정** |
| `createdAt` | 서버 시각(`ServerValue.TIMESTAMP`)만 허용. 앱 모델은 epoch ms `long` |
| `userChatRooms` | 서버가 갱신(BT-034 채팅방 생성, 메시지 트리거). 앱은 본인 `unreadCount`를 0으로만 쓸 수 있다 |
| `status` | Firestore `matches.status`(`ACTIVE`/`ENDED`)를 서버가 복사한 값. 원본은 Firestore |
| `hidden` | 채팅방 나가기(BT-043). ENDED 검사가 필요해 Callable에서 서버가 쓴다 |

## 2. 보안 규칙 요약 (`database.rules.json`)

| 경로 | 읽기 | 쓰기 |
|---|---|---|
| 루트·`chatRooms/{matchId}` 전체 | 거부 | 거부 |
| `chatRooms/{matchId}/members` | 그 방의 멤버 | 거부(서버 전용) |
| `chatRooms/{matchId}/messages` | 그 방의 멤버 (`.indexOn: createdAt`) | 멤버가 **새 메시지만** 생성. 수정·삭제 금지, 필드 3개 외 금지 |
| `userChatRooms/{uid}` | 본인 | 거부. 예외: 본인·기존 항목의 `unreadCount = 0` (삭제는 거부) |

- ENDED 방에서도 전송할 수 있어야 하므로 **규칙은 매칭 상태를 검사하지 않는다**(종료는 차단이 아님).
- 서버(Admin SDK)는 규칙을 우회하므로 BT-034 채팅방 생성 함수 안에서 참여자를 직접 검증해야 한다.
- RTDB 규칙의 정규식은 `\s`·`\S`를 지원하지 않고, 정규식 안의 `\t`·`\n`도 공백 문자로 해석되지 않는다. 그래서 공백 검사는 `replace(...)` 후 길이로 한다.

## 3. Android 구조 (`chat/`)

| 클래스 | 역할 |
|---|---|
| `ChatRepository` | 기존 인터페이스 그대로(BT-009·010). 콜백 + `Registration` |
| `ChatRepositories.get(context)` | 저장소 선택. Firebase가 초기화되면 `FirebaseChatRepository`, 아니면(CI·`google-services.json` 없음) `MockChatRepository.shared()`. 로그인 UID가 바뀌면 새로 만든다 |
| `FirebaseChatRepository` | `observeRooms`(`userChatRooms/{uid}`), `observeRoom`(`userChatRooms/{uid}/{matchId}`), `observeMessages`(`messages` `createdAt` 순 최근 100개). 해제 후 늦은 콜백 무시. 권한 거부·RTDB 주소 없음·로그인 전은 `onError` |
| `ChatRtdbMapper` | RTDB 값 ↔ `ChatMessage`·`UserChatRoomEntry`·`ChatRoom`. 형식이 틀린 노드는 건너뛴다 |
| `ChatRoomsCombiner` | 목록 항목에 매칭 스냅샷·상대 프로필을 붙인다. 새로 생긴 방만 구독하고 사라진 방은 해제 |
| `MatchInfoSource` / `PartnerSource` | 매칭 스냅샷(`matches/{matchId}`)·상대 공개 프로필(`publicProfiles/{uid}`) 출처 |

**아직 연결하지 않은 것**

- `MatchInfoSource`: 지금은 `UNAVAILABLE`. D의 BT-031이 `matches`를 만든 뒤 **BT-034**에서 Firestore 구현을 붙인다. 그 전에는 `meetingDate = null`, 시간 0, 상태는 `userChatRooms.status`.
- `PartnerSource`: 지금은 `UNAVAILABLE`(이름 "상대"). BT-014(#79)는 병합됐지만 `ProfileRepository`에 다른 사용자의 `publicProfiles`를 읽는 메서드가 없어 B와 방식을 맞춘 뒤 연결한다.
- `sendMessage`·`markRead`: BT-022. `endMatch`: D의 BT-038. `leaveRoom`: BT-043. 그 전에는 `onError`(markRead는 무시).
- 화면(`ChatListFragment`, `ChatRoomActivity`)은 아직 `MockChatRepository`를 쓴다. BT-022에서 `ChatRepositories.get`으로 바꾸고 고정 UID `"me"`를 제거한다.

## 4. 테스트

```bash
# 앱 단위 테스트(변환기·조립기 포함)
gradlew.bat testDebugUnitTest

# Rules 테스트(로컬 RTDB 에뮬레이터, functions/emulator-tests/chat-rules.test.ts)
firebase emulators:exec --project demo-bintime --only database "npm --prefix functions run test:emulator"
```

`npm --prefix functions test`는 에뮬레이터 테스트를 제외한다(`emulator-tests/**`). 에뮬레이터 테스트는 `FIREBASE_DATABASE_EMULATOR_HOST`가 없으면 건너뛰고, 로컬 주소가 아니면 실행을 거부한다.

### google-services.json 확인

실제 RTDB(에뮬레이터가 아닌)로 앱을 테스트하는 사람은 먼저 확인한다. RTDB가 미국 외 리전(asia-southeast1)이라, RTDB를 만들기 전에 받은 `google-services.json`에는 `firebase_url`이 없어 앱이 RTDB에 접속하지 못한다.

1. 앱 모듈의 `app/google-services.json`에서 `project_info.firebase_url` 값을 확인한다.
   ```bash
   grep firebase_url app/google-services.json
   ```
2. 값이 `https://bintime-mobile-default-rtdb.asia-southeast1.firebasedatabase.app`이 아니거나 줄이 없으면, Firebase 콘솔 → 프로젝트 설정 → 내 앱(Android)에서 파일을 다시 받아 덮어쓰고 Gradle Sync를 다시 한다.
3. 이 파일은 계속 커밋하지 않는다(README 7장).

## 5. 에뮬레이터로 채팅방 만들어 보기

실제 채팅방은 BT-034에서 서버가 매칭 수락 후 만든다. 그 전에는 로컬 에뮬레이터에 시드한다. **실제 RTDB에는 쓰지 않는다.**

1. 에뮬레이터 실행 — 앱의 네임스페이스(`bintime-mobile-default-rtdb`)에 규칙이 적용되도록 프로젝트 ID를 맞춘다. 로컬에서만 동작한다.
   ```bash
   firebase emulators:start --only database --project bintime-mobile
   # 로그인도 에뮬레이터로 할 때만: --only auth,database
   ```
   실제 프로젝트 ID를 쓰므로 **반드시 `--only database`(필요하면 `auth,database`)로만 띄운다.** `--only` 없이 실행하면 `firebase.json`의 Functions 에뮬레이터까지 함께 떠서, 에뮬레이터가 아닌 서비스(실제 Firestore·Gemini 등)를 호출할 수 있다. 앱 연결 없이 Rules·시드만 확인할 때는 1·2단계 모두 `--project demo-bintime`을 쓰고 `--ns`를 생략한다.
2. 시드 — 내 UID는 앱에서 로그인한 계정의 UID(Firebase 콘솔 Authentication 또는 로그)를 쓴다.
   ```bash
   npm --prefix functions run seed:chat -- --me <내 UID> --ns bintime-mobile-default-rtdb
   ```
   진행 중(ACTIVE) 방 1개와 종료(ENDED) 방 1개, 메시지, 양쪽 `userChatRooms`를 만든다. 같은 인자로 다시 실행하면 같은 방을 덮어쓴다. 호스트가 `127.0.0.1`/`localhost`가 아니면 거부한다.
3. 앱 연결(디버그 빌드만) — `app/src/debug/res/values/config_chat_local.xml`을 만들고 커밋하지 않도록 `.git/info/exclude`에 등록한다.
   ```xml
   <resources>
       <!-- Android 에뮬레이터는 10.0.2.2, 실기기는 adb reverse tcp:9000 tcp:9000 후 127.0.0.1 -->
       <string name="chat_rtdb_emulator_host" translatable="false">10.0.2.2</string>
   </resources>
   ```
   값이 비어 있으면(기본 `res/values/config_chat.xml`) 실제 RTDB를 쓴다. 릴리스 빌드는 디버그 리소스를 포함하지 않는다.

> 화면 연결은 BT-022이므로, BT-021 단계에서는 시드 데이터를 화면으로 확인할 수 없다. 앱 실행 확인은 BT-022에서 한다.
